## 1. SCS1 sidecar 文件整体布局

```
┌───────────────────────────── offset 0
│ ScsHeader            96 B
├───────────────────────────── offset 96
│ ScsMeshRecord[0]     48 B   ┐
│ ScsCardPageEntry ×N0 48 B/条 │ mesh 0
│ ScsMeshRecord[1]     48 B   │
│ ScsCardPageEntry ×N1 48 B/条 │ mesh 1
│ …（mesh_count 个）            ┘ 记录区
├───────────────────────────── records_end = 96 + Σ(48 + 48·Ni)
│ 页平面数据（连续，无间隙）
│   mesh 0 card 0: [albedo][normal][depth][params][triangle]
│   mesh 0 card 1: [albedo][normal][depth][params][triangle]
│   …（按 mesh 升序、卡序升序）
└───────────────────────────── EOF
```

- **记录区与页数据分离**：读 header+记录只需一次顺序读；页按需 `fseek+fread` 单卡表面及 TriangleID 平面（`SurfaceStaticPages::ReadCardPlanes`），CPU 无全量驻留。
- 每平面字节数 = `resolution² × 4`（五种平面统一 4 B/texel——见 §3）。
- `ScsCardPageEntry.{albedo,normal,depth,params,triangle}_offset` = 文件**绝对字节偏移**，指向该平面的首 texel。

## 3. 页平面格式与 texel 排列

**texel 线性序 = row-major**：`texel = py × R + px`（py = 行/v 方向，px = 列/u 方向），`px,py ∈ [0,R)`。五个平面同序。

| 平面 | 格式 | 4 B 布局（小端） | 语义 |
|---|---|---|---|
| albedo | RGBA8 **线性** | `[r,g,b,coverage]` | rgb = sRGB 纹理双线性 × tint × albedo_scale 转 linear 后再量化 255；**coverage: 255 = 有效表面，0 = 无覆盖（显式无效，§3.2 禁伪有效）** |
| normal | RG16F（两枚 IEEE754 half） | `[f16(e0)][f16(e1)]` | oct 编码 [0,1]²（见 §5）；**mesh 局部空间、朝卡眼（dot(N,fwd)≤0），未经实例变换** |
| depth | R32F | `[f32,0,0,0]` | **卡局部轴向距离** `t`：texel 中心沿卡 `fwd` 的首命中距离，∈(0.05, 2·extent_axis+0.5]；未命中 = `-1.0` |
| params | RGBA8 | `[roughness,metallic,emissive,flags]` | 当前 MaterialInstance 默认值占位（128/0/0/0）；SC 消费方尚未读取 |
| triangle | R32_UINT | `[u32]` | 原始索引缓冲的三角形序号（firstIndex/3），无效为 `0xffffffff`；与 coverage 一致，禁止插值。geometry_digest 定义编号空间；BVH 重排不改变编号。 |

**texel 中心 → 卡平面点**（烘焙与 GPU 合成同式，与运行时查询契约 `cardTexelToWorld` 一致）：

```
u = (px + 0.5) / R,  v = (py + 0.5) / R
p_local = card.center + u_axis · (u−0.5)·2·extent[u_axis]
                       + v_axis · (v−0.5)·2·extent[v_axis]
射线：origin = p_local，dir = fwd（卡单位法向，含 dir 符号），双面首命中 → t = depth
```

**卡片坐标系**（与 `SurfaceCacheData.glsl` 逐约定一致）：

| axis_direction 低字节 axis | 深度轴 fwd | u 轴 | v 轴 |
|---|---|---|---|
| 0 (X) | ±X（dir 位定号） | **+Y** | +Z |
| 1 (Y) | ±Y | **+X** | +Z |
| 2 (Z) | ±Z | **+X** | +Y |

- capture 光栅的 **U 镜像只是对齐机制**，烘焙/查询/合成约定**无镜像**。
- 源 UV 的 `uv.y = 1−uv.y` 翻转在**纹理采样行号**处理（`row = (1−v)·H`），不改页坐标。

## 4. 三摘要（键控）计算

`ComputeCardBakeDigests`（`RHIMeshAsset.h`，运行时）与 `CardSurfaceBake.cpp bake_mesh`（离线）必须逐字节同输入：

```
geometry_digest = FNV-1a64( seed=0xcbf29ce484222325;
    u32 num_vertices, u32 num_indices,
    position_buffer 原始字节,      // 12 B × V
    index_buffer 原始字节, element_buffer 原始字节 )        // ⚠ blob 原生宽度（u16/u32），不是展宽副本
layout_digest   = FNV-1a64( seed=0xcbf29ce484222325; cards[] 原始字节 )  // 32 B/张
```

运行时 `ResolveStaticSlot(g,l,m)` 三摘要全等才返回槽位；任一不等 = INVALID = 该 mesh 走原 capture 路径（**不读旧页冒充新数据**）。

同一几何/布局允许多个材质记录；`mesh_count`计记录而非唯一几何。每个(g,l,m)对应自己的完整页目录与payload，`FindMesh`仅选当前材质摘要全等的记录，不叠加分配重复card。材质变体只改变纹理/材质摘要与albedo，原始TriangleID、depth、normal和PBVH几何摘要保持一致，无需重建BLAS/TLAS。

离线`sc-bake-surface --texture-variant <纹理路径子串>:<线性比例>`可重复添加变体，同时保留原纹理页。变换作用于解码RGBA8的RGB（alpha不变）：sRGB解码→线性乘比例/钳位→sRGB编码/`+0.5`后转u8；烘焙与参考场景共用`CardSurfaceIdentity::ScaleTextureRgb`，计算纹理摘要发生在量化之后。任一未匹配/缺失变体源拒绝；重复摘要不生成重复变体。`--albedo-scale`是全局采样/tint比例，不可替代源纹理字节变换。


## 5. oct 法线编码（与运行时 MathLib.glsl `octEncode` 同式）

```
p = n.xy / (|n.x|+|n.y|+|n.z|)
若 n.z < 0： p = (1−|p.yx|) · sign(p.xy)
e = p · 0.5 + 0.5          // [0,1]²，量化进两枚 f16
```

## 6. 运行时 GPU 消费布局

- **页字节池 SSBO**（合成 pass binding 4，`std430 uint pool_words[]`）：按静态卡 atlas 装箱序连续排列，每卡 `[albedo R²·4B][normal R²·4B][depth R²·4B]`；R 是 32 的倍数 → 全部 4 B 对齐，按 uint word 寻址（`StaticCompositeInfo.meta2[0..2]` = 三平面 word 基址）。
- **StaticCompositeInfo**（`SurfaceCacheTypes.h`，144 B = 9×vec4，与 shader 镜像）：`meta0 = atlas_offset_x/y, card_res, page_res`；`meta1 = texel_offset, count(首条), world_axis_dir, local_axis_dir`；`meta2 = albedo/normal/depth/TriangleID 四平面 word 基址`；`center_w + mcol0..2`（实例世界矩阵线性列）；`local0 = emissive RGB, extent.x`；`local1 = extent.yz, pad×2`。
- **卡片静态身份**（`SurfaceCacheCard._pad1[0..2]` / GLSL 镜像 `static_mesh_slot, flags, page_card`）：flags bit0 = static——capture 与 CardFill 的跳过谓词。
- **CardDispatchInfo._pad1**（GLSL）/`_pad[0]`（C++）bit0 = static——CardFill dispatch 级跳过。
- **射线 lookup 统计**（resolve binding 17，15×u32 原子累加）：`[0]queried [1]found [2]Δ≤0.05 [3]≤0.15 [4]≤0.45 [5]>0.45 [6..13]reject 1..8 直方图 [14]保留`；`PRIMAL_SC_RAY_LOOKUP_STATS=1` 时每 30 帧追加 JSON 行到 `/tmp/sc_ray_lookup_stats.log`。

## 10. 首命中诊断与 owner 表（2026-09-30 后续）

SCS1 v3 将 near/far 契约写入 header，拒绝旧 v2 的3倍深度烘焙；header仍96B，mesh record仍48B。离线和实时共享 `CardSurfaceIdentity.h` 中 near=.05、farScale=1、farBias=.5。运行时 near 配置不同则静态页回退。

Tile trace使用三缓冲CPU生成的直接owner表，覆盖全部已分配卡（Vulkan binding12 / Metal buffer4），而不是只扫描前24张卡；每tile按中心唯一归属，未分配或重叠保持无效。分配纪元或tile尺寸改变时刷新；trace只绑定实际card count，拒绝非有限depth/position/normal。

实验开关 `PRIMAL_SC_RAY_DDA=1`（默认关闭，resolve flags bit2）采用二维texel DDA：裁剪到卡UV/depth域，按射线次序跨越格子并检查每格的axis-depth交点，不因初始洞/初始投影越界而直接失败。每卡最多2R+2步；这是单层离散深度表面的首命中，不等价于原三角形首命中。

`SC_RAY_ORACLE_PREFIX` 默认不设置，设置后 resolve flags bit1开启只读诊断（bit0仍是生产ray候选）。统计缓冲扩展到16+16384×16个u32；每37条射线抽样1条，记录实际原点/方向、SDF结果、SC结果和最后有效刷新stamp。`SC_RAY_ORACLE_FRAME`（默认350）在帧后checked copy导出`.samples.bin`（8B count/stride +64B/条）与`PGRAYS01` `.rays.bin`。采样包含SDF surface/sky，排除cone-occluded/INVALID；stamp反映各tile最后有效刷新，非全表同一帧。padding保存原点不改变ProbeRayHit的32B ABI。

`scripts/sc_ray_first_hit_audit.py prepare/evaluate` 对接已有GPU场景三角形BVH证明，并使用float64 CPU遍历同一resident BVH交叉校验，先验证原始ray输入逐位一致，再分类miss/false-sky/错误首表面。无alpha/透射认证，只证明双面三角形几何。

## PBVH0001 持久化格式（2026-10-01）

实现：`Engine/Graphics/Utilities/GeometryBVHStore.{h,cpp}`。与SCS1共享`ComputeGeometryDigest`；文件为little-endian，头64B：

| offset | 字段 | 说明 |
|---|---|---|
| 0 | char magic[8] | PBVH0001；格式版本1 |
| 8 | u32 endian | 0x01020304 |
| 12 | u32 kind | 1=mesh BLAS，2=完整两层场景快照 |
| 16 | u64 source | BLAS=GeometryDigest；场景=InstanceID＋GeometryDigest＋world matrix列表摘要 |
| 24 | u64 payload | 所有数组逐字节FNV-1a64，校验完整性 |
| 32 | u32 counts[4] | TLAS node / BLAS node / triangle / instance 数量 |
| 48 | u64 reserved[2] | 必须0 |

payload顺序为四组数组：48B node (`float lo[4], hi[4]; u32 left,right,first,count`)，48B triangle (`float a[4],e1[4],e2[4]`)，64B instance (`float inverse_rows[3][4]; u32 root,InstanceID,GeometryDigestLo,GeometryDigestHi`)。node内部count=0、leaf count>0。TriangleIndex保存在a.w的u32位模式中，不是浮点数值；只在本mesh范围内编号。kind1没有TLAS/instance数组，原三角形索引必须唯一覆盖0..N−1。kind2保存完整下层数组，每个mesh根可被多个instance引用，不能按scene-global TriangleIndex理解原mesh索引。

默认`.primal-cache/geometry-bvh/<digest>.blas/.tlas`；派生缓存不入git，删除可重建。加载前验证version、长度（上限512MiB）、checksum、树结构及数值，失败不上传GPU；运行时对SC注册身份再次核验。Scene snapshot随实例或变换变化失效；mesh BLAS随统一geometry摘要变化失效，纹理/材质变化只影响独立SC材质身份。SCS1 v4追加每texel原始TriangleID，与PBVH原始TriangleIndex对应。Vulkan候选以同实例＋同TriangleID＋0.05m点一致性校验；单层覆盖与物理页容量仍独立限制命中。

## 2026-10-01 v4 GPU 身份接线

静态合成仍使用144B StaticCompositeInfo，meta2.w为TriangleID页在pool_words内的基址。与颜色/法线/深度共享同一ptex最近邻采样，写入独立4B/atlas-texel的uint SSBO；AtlasInit在分配纪元变化时写无效sentinel。Vulkan静态合成与初始化均增加binding6。几何trace变体18绑定（追加binding17射线TriangleID）；resolve几何变体20绑定（18射线ID、19atlas ID），默认trace13/resolve18不变。ProbeRayHit仍32B。显式compute写→compute读屏障覆盖身份缓冲。Metal保留capture路径，无TriangleID消费，不声明跨端GPU对等。


## 2026-10-03：可选完整TriangleID成员目录（仅内部GPU索引，SCS1不变）

`PRIMAL_SC_CARD_TRIANGLE_FILTER`默认未启用。显式0/1均构建相同内部成员目录，只有1设置resolve的bit8192，供同binary/SPIR-V性能对照；未知/异常目录回到原候选检索。

`TriangleSupportIndex`的SCH1主体保留4字头、每card两字目录和排序三字记录`{TriangleID, sourceOffset, hullCount}`。显式构建成员目录时，记录包含该card所有非`0xffffffff`的原始ID，含单点、透明和无效深度；无法形成合法凸包的记录`hullCount=0`，原`scIndexedSupport`仍拒绝其支持采样，不能把ID存在升级为光照可用。仅完整、有效、当前epoch且正对角变换/同分辨率的静态页生成可信状态。

主体后追加每card一字`complete`（0未知，1完整，包括完整空card），再追加四字footer `{0x53435031, completeOffset, cardCount, legacyEnd}`。头`words[3]`仍为legacyEnd，旧凸包消费者不读取footer。新`scTrianglePresent`验证magic、完整边界/数量及状态，再对原排序ID作整数二分检索；完整目录未命中才拒绝，未知或格式异常返回“可能存在”。CPU完成footer后拒绝继续Add，重复Finalize幂等；容量检查预留footer，构建失败的card不获完整认证。无新增descriptor、C ABI或SCS1磁盘字节/版本修改，Metal/Dawn没有声称实现此Vulkan实验路径。

实际Sponza GPU读回审计：2449可信静态card、83未知活跃card、39可信空card、156967 `(card,ID)`成员；上传完整索引787279字/3149116B，原仅凸包索引611679字/2446716B，增加702400B。实际atlas成员无漏项也无额外ID；整数absence过滤仍须保持原UV/面向/范围检查、模式优先级和拒绝位。实现及同版本ABBA/视觉回归证据见实现完工记录和阶段网页。


## 2026-10-03：可选owner/TriangleID掩码扩展（内部GPU索引）

`PRIMAL_SC_OWNER_TRIANGLE_MASK`默认关闭，显式0/1均构建相同payload，1在完整card过滤bit8192的条件下加bit32768。仅Vulkan实验几何路径消费；不修改SCS1磁盘格式、既有descriptor或C ABI。

布局：SCH1旧主体（header `words[3]=legacyEnd`）→owner七字目录及三字ID记录→五字SCO1 footer→每card complete→原四字CSP1 footer。owner行为`{firstCard, span, unknownLo, unknownHi, recordOffset, recordCount, enabled}`；跨度是首末card的差+1，1..64，允许其他owner的间隙但这些位置的bit必须0；未知card位在任何ID查询中保留。排序记录为`{TriangleID, cardMaskLo, cardMaskHi}`。SCO1 footer为`{0x53434f31, ownerDirectoryOffset, ownerCount, ownerPayloadEnd, legacyEnd}`，其中directoryOffset等于legacyEnd，payloadEnd指向该footer首字。该footer在CSP1的completeOffset之前5字；CSP1仍位于整个buffer最后4字。没有owner扩展时沿原布局，completeOffset等于legacyEnd；有扩展时completeOffset大于legacyEnd。

shader验证所有目录/记录边界、magic、owner范围与原已验证card范围完全匹配后，每query一次整数二分查找，实际允许位=unknown OR匹配ID mask；目标ID缺席只返回unknown。最多65536 ID，17次二分足够；未知、超64、过大目录/容量/格式异常均回原逐card存在检查。Add在任意Finalize之后拒绝；FinalOwnerMasks必须先于FinalPresence，构建失败不发布半截payload，重复调用幂等。旧hull消费者仍仅以legacyEnd为上界，完整card消费者允许completeOffset≥legacyEnd。

实际GPU全量审计393 owner、389有效/4缺席，85429 owner-ID条目、156967 card-ID对、83未知card，无漏项/额外位；1046322字/4185288B，比完整card成员目录多1036172B。该CPU审计读取实际GPU buffer，不等于孤立shader自测；边界CPU SC213/213。ABBA与最终回归范围见实现记录。

### 2026-10-03 原源页点作为独立SCB1支持与GPU资源上限

SCB1版本/36B样本/三摘要不变，样本可来自原SCS1有效texel的真实位置和原始ID/量化表面属性；生成时以CDB2坐标还原并验证原primitive，不把邻近texel的位置挪到目标query。独立文件合并保留原记录样本，实际GPU每card域/侧打包，故bank记录数不等于SCB1样本数。共享GPU点上限131072统一pack/mixed/cache/radiosity（旧三处16K拒绝已修复），每组8192与index4M words仍独立约束，超限失败不截断。原资产未替换，owner16/18/7源扩充仍是独立实验，当前记录见实现顶部。
