# Primal 通用制作能力总规划

> 日期：2026-10-04；状态：📋 规划，未实施。
> 本文定义方向、模块边界、共用契约与验收原则；各领域独立推进，阶段和最终目标见子文档。拟议接口不表示现有实现。

## 1 产品方向

Primal 以自身渲染特色、通用基础运行和容易使用的制作工具为核心；LLM、Agent、harness 与 Skills 作为可选制作助手，串联外部软件。harness 指 Agent 的上下文与工具运行环境。各领域可以单独建设，不安排全引擎统一的第几期，不要求先装齐所有外部软件。

“基础”指功能范围克制，但使用闭环完整：能创建、编辑、预览、保存、重开、导出、运行、诊断和恢复。游戏题材逻辑由项目定义；模型制作、绑定、切片等优先连接成熟工具。基础能力手工操作与 Agent 调用共享同一事实源。

## 1.2 范围状态：不做、暂缓、外部接入与可选扩展

规划覆盖一个领域，不代表该领域的所有功能都需要自研。以下状态是产品范围决定，与“未实现/部分实现/已实现/已验收”的实现状态分开记录。

| 范围状态 | 含义 | 如何使用 |
|---|---|---|
| 核心建设 | 通用基础能力及完整使用闭环 | 在对应子模块定义阶段和验收 |
| 不纳入引擎内置 | 项目或外部工具负责，引擎提供必要接口 | 不列为引擎欠缺的必做功能；保留项目扩展能力 |
| 暂缓 | 当前不实施，以后有明确需求可重新立项 | 保留占位，不等同永久不做 |
| 延后／已有专项推进 | 此规划暂不另行启动，现有专项继续 | 保留目标和验收，接入已有成果，不创建重复建设任务 |
| 外部接入优先 | 需要该能力，但优先做适配、数据交换和诊断 | 不把“不自研”误写成“不支持” |
| 可选扩展 | 不属于通用基础必需项 | 有具体项目需求再选择，不能悄悄成为基础验收前置条件 |

### 已有用户决定与规划建议

| 具体能力/目标 | 范围状态 | 决定依据与保留部分 |
|---|---|---|
| 全部渲染相关建设（含材质） | 延后／已有专项推进 | 用户明确决定：渲染已有工作在做；此规划不另行启动 RHI、GI、反射、阴影/灯光、Nanite/GPU Driven、材质、VT、雾/大气/后处理建设；现有专项继续 |
| 全面复制 Unreal 的全部功能与视觉路线 | 不作为产品目标 | 依据用户方向：自身渲染特色、多 API 对齐；仍建设稳定性、性能、制作控制与实际画面验收 |
| 内置特定游戏的战斗、背包、任务、技能树及专用 AI 规则 | 不纳入通用引擎内置 | 依据用户希望玩法/UI/AI 提供基础支持；保留脚本、属性/事件、基础 UI、移动/导航与项目扩展，不禁止项目实现这些功能 |
| 多人复制、RPC、匹配、预测纠正、专用游戏服务器 | 暂缓 | 用户明确希望网络先留空；云 API、MCP、软件通信、设备数据与云交付不受此决定限制 |
| 骨骼绑定、复杂动作制作与重定向工具 | 外部接入优先 | 用户倾向 Tripo 等外部方案；保留骨骼导入、蒙皮、动作运行与诊断，不据此认定永远不能增加内部编辑工具 |
| 自研通用 CAD/BIM 编辑器、FEA/CFD 求解器 | 外部接入优先（规划建议） | 工业/仿真仍需建设；引擎负责场景、语义、任务、结果与交互，求解/专业建模优先成熟工具；这不是用户确认的永久排除 |
| 自研切片器、打印机驱动、设备闭环控制 | 暂不自研（规划建议） | 保留打印检查/导出/切片衔接；设备控制有明确项目需求时独立评估 |
| 高级 IK/Control Rig/运动匹配、战术 AI、车辆/布料/破坏专项、全量电影剪辑工具 | 可选扩展 | 不作为通用基础模块完成条件；各自可按项目需求展开，不删除领域规划 |
| 同时接入所有行业格式、设备协议、软件与 harness，或同时实现 Web 与云渲染 | 不作为全量完成要求 | 规划建议：支持清单逐项声明并验收；接口通用不等于承诺所有生态立即兼容 |
| 启动前强制安装全部软件、所有功能强制接 LLM、每次启动运行昂贵验证 | 不采用的产品流程（规划建议） | 基础编辑与本地流程独立可用，外部能力按需接入；这属于易用性设计约束 |

目前没有用户确认的“永久排除整个物理/流体/大世界/工业/工程仿真领域”的清单。明确不需要纳入通用引擎的题材功能、暂缓项、外部负责项和可选项必须分别标注；规划建议不能冒充用户已确认的取舍。任何新增永久排除决定，应记录用户决定依据，并同步对应子文档与覆盖表。

### 渲染延后与其他模块的分工

渲染及材质子文档保留为后续目标与验收参考，其中 S1/S2/S3 全部延后，不代表当前待启动任务。已有渲染专项继续按其自身文档推进，本次范围调整不暂停或改写正在进行的工作。

PFX、流体、地形、大世界、角色动画、运行时 UI、Sequence 和 Web 等模块仍可独立推进非渲染功能；其中新增着色、GI/光照联动、专门表面渲染、后端扩展及画质优化属于渲染建设，随本决定延后或与现有专项协调。现有显示能力、UI 排版和实际输出的视觉验收继续保留，不能把“渲染延后”当作跳过可用性/视觉验收的理由。

其他模块优先使用已有渲染接口和能力验收；遇到必须新增渲染才能完成的功能，明确标记该功能待协调/待渲染支持，不把未完成内容标成通过，也不以此停止整个模块的独立基础工作。

## 1.3 现有代码基线与调整

已有 PCG/PFX 制作、脚本内核、物理控制、资产 GUID/索引、Prefab 文档/实例化、编辑器恢复、帧输出/编码和 WASM Demo 优先复用。重点补生产接通与交互深度，不从零重建这些系统。Player 组件导出/加载/tick 与实际 cooked 产物、可搬移资源是共享断点；StreamingMesh/SurfaceNets/meshlet Validator 等相近基础不能算完整大世界/地形/打印功能。

本次只有静态代码评估，没有运行测试或交互/视觉验收；“已有实现”与“已通过验收”仍严格区分。渲染/材质继续延后。

## 2 独立推进与共用接口

不建立一个必须按顺序完成的总路线。各子文档的 S1/S2/S3 仅表达本领域从最小可用到完整目标的递进，不代表日期、统一发布批次或资源承诺。实施某模块时，再细化该模块当期任务、负责人、夹具、平台和验收记录。

各模块可从本地样例独立验收：角色用本地文件，导航用基本几何，UI 用静态模板，Sequence 先属性轨，打印用标准零件；云账号、角色动画、Agent 和软件中心不能成为所有模块的前置条件。

| 共用契约 | 负责方向 | 使用者与约束 |
|---|---|---|
| 属性/事件描述 | 脚本与属性模块 | Inspector、Sequence、UI、Agent；稳定 ID/类型/单位/所有权一致 |
| 编辑态命令 | 现有 CLI Registry 与文档模型 | UI/CLI/MCP 走 Scene/GameEntity 和 UndoRedo，不另造原生状态源 |
| 软件/capability/Skill 记录 | 集成中心 | 任务和 UI 共用，安装存在与任务能用分开 |
| 任务/产物清单 | Agent 与流水线 | 资产转换、生成、打印和帧输出可独立接入；输入版本可追溯 |
| 源/派生资产身份 | 资产管线与各领域 | 重导入、修复、动画、打印副本；原件保留，失败不静默覆盖 |
| 单位/坐标/时间/质量 | 工业、GIS、设备数据、工程仿真与基础模块 | 源语义保留、误差/过期/未知明确；不能用实时视觉效果替代工程精度 |
| 运行与导出 | 每个运行模块 | 编辑器、保存重开、Player 保持声明的行为一致 |
| 发布/版本/恢复 | 发布维护与资产/编辑器 | 支持平台、可重复产物、迁移、更新/回退和故障诊断 |
| 画质/后端契约 | 渲染模块 | 各领域新增图形路径明确支持或降级，不假定所有 API 全等 |

具体命令按仓库单一 schema 扩展，文档中的接口概念不能直接当现成命令使用。修改代码遵循 [AGENTS.md](../AGENTS.md)，文档登记遵循 [ARCHIVE.md](ARCHIVE.md)。

## 3 通用与容易使用的标准

各领域子文档已补充“详细设计与接口契约”“不做项目与范围边界”“严格阶段、任务拆分与退出条件”“实施决策与变更记录”。每阶段的交付范围、任务顺序、参考结果、失败判据、交互预算和交付端分别列出；阶段表表达最终范围，不要求重写现有实现。没有后端/工具选择的项必须先完成小样与决策冻结，不能把规划概念命名当作现成 API。

共同规则见 [严格阶段与验收合同](plans/production/stage-acceptance-contract.md)，实际证据使用 [验收记录模板](plans/production/acceptance-record-template.md)。两份辅助文档不增加领域模块，也不建立全引擎统一排期。量化指标是拟议验收目标，尚未测得；必须在实施前绑定支持范围/机器/夹具，保留调整依据。

每个模块提供可直接使用的默认值和小模板，基础操作优先选择器、拖放和即时预览；高级参数按需展开。用户不需要了解 EngineDLL、修改场景 JSON、复制内部 ID 或重编引擎来完成基础流程。

外部依赖按任务出现，只解释当前缺项；一次性安装/登录/许可证设置与每次制作的操作成本分别记录。允许有依赖，不能隐藏代价。通用性通过不同题材/资产样例复用验证，不能为每个样例新增特例代码。

支持清单限定平台、后端、格式、工具/协议版本和输入范围。未知/未验证显示为未知；可扩展接口不等于已有实现。外部 Skill 文件、适配器、软件安装和验证过的能力分别管理。

## 4 统一验收：四个门禁同时通过

“代码无 bug”不能用有限测试证明为绝对命题。本规划将其落为：已声明行为与边界测试全部通过，覆盖范围内无已知阻断/高严重度缺陷，无相关回归；剩余限制明确记录。测试数量、冒烟通过或长时间运行都不能替代功能正确性和真实使用验收。

| 门禁 | 必须验证的内容 | 通过证据 |
|---|---|---|
| A 代码与数据正确 | 正常结果、边界/无效输入、生命周期、保存重载、Undo、导出/Player、取消/失败恢复；按模块适用 | 可复现夹具、预期值/参考结果、自动测试报告、缺陷闭环；实际外部工具成功路径 |
| B 完整交互 | 在真实编辑器/Player/外部软件完成用户目标；首次使用、重复使用与一次失败修复 | 操作录像、完成率、错误/人工帮助记录；非实现者无口头指导验证 |
| C 使用与额外成本 | 操作次数、耗时、安装/账号/许可证、手工转换、路径复制、调参、返工、额外软件打开次数 | 一次性与每次成本分别记录，满足子文档预算；没有隐藏的必需步骤 |
| D UI 与最终视觉 | 面板层级/对齐/留白、字体、焦点、状态、响应/错误反馈，及实际场景/动作/导出画面 | 真实界面截图与内容视频，DPI/窗口/平台覆盖，人工逐项确认和视觉回归 |

对不涉及 Player/Undo 的离线模块，写明不适用原因；对图形路径，加入对应 API/画质档测试。需要引擎改动时运行仓库要求的回归，但回归门禁只是 A 的一部分。

### 4.1 交互验收怎么执行

每阶段至少设一个首次使用场景、一个重复制作场景和一个失败恢复场景；写清输入、用户目标、步骤预算、期望数据与期望画面。完成真实“创建/导入→配置→预览→保存重开→交付/运行”，不能只看终端退出码。

至少由三名未参与实现的人按产品内提示完成任务，每人独立完成必需目标，测试期间作者口头指路次数为 0；作者可先自测，作者独自演示不能代替可用性验证。被测者使用正常文档/内置帮助，测试者不口头指路。记录卡住、误解、撤回、求助和修复操作；若当前只有作者可测，将 B 标为待验收。修复后复验保留首轮失败证据，不能只展示最终成功录像。

各子文档的点击预算为初始目标，实施前结合原型/代表任务冻结。统计“有意操作”（点击、拖拽、选择、输入提交），不把连续键入的每个字符当点击；系统选择器内部、一次性安装也必须独立记录。不得在失败后放宽预算以宣称通过。

### 4.2 视觉与成本怎样算合格

声明最低可用窗口尺寸；至少在 100%/150%/200% 缩放下检查实际支持平台，无截断、重叠、无法访问的主要操作。长名称、中文、空/加载/失败/禁用状态均检查，状态不能仅靠颜色区分。视觉确认包括交付内容，不能只展示 UI 原型或渲染 mockup。

在代表机器记录首次可用时间、操作到反馈的延迟和长任务进度/取消；冻结预算后评估，不能把所有等待隐藏到“后台”。首次安装总时间与许可证/账号成本明确；重复任务不得反复要求同样的手工修配置。没有外部工具时要能解释并走手工导入等适用退路。

### 4.3 每个阶段保留的验收记录

| 字段 | 内容 |
|---|---|
| 声明范围 | 模块/阶段、代码与文档版本、平台/API、软件与格式版本、支持限制 |
| 场景 | 输入夹具、目标、预期数据/画面、步骤/时间预算 |
| 自动验证 | 测试结果、参考值、失败边界、相关回归 |
| 实际使用 | 录像/截图、操作者、完成时间/步骤、求助与返工 |
| 成本 | 一次性环境投入、每次任务成本、额外服务费用或权限 |
| 结论 | A/B/C/D 分别通过/失败/待验收；缺陷链接、修复复验、遗留限制 |

任一必需门禁失败或待验收，阶段不能标“已完成”。自动化覆盖外部服务故障可用模拟器，但不能替代声明适配的软件实测成功路径。

## 5 软件检测页面的结论

有必要做，建议采用“启动页入口/摘要 + 项目内可访问的集成中心”，它帮助用户理解软件、能力与 Skills 的关系，并定位制作流水线缺项。它不是启动必经步骤，不自动安装全部软件，不在每次启动进行昂贵或付费验证。

界面同时呈现内部与可发现的外部 Skills，明确来源、依赖与验证状态；无法读取外部 harness 的清单时显示未知。安装但无 Skill、Skill 存在但缺软件、云服务没有本地应用这三类情况都要表达。具体 UI、状态与阶段验收见 [集成中心子规划](plans/production/software-integrations-and-skills.md)。
