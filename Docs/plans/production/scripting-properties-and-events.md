## 最终目标

项目用少量脚本接入自定义玩法，能安全查询/修改组件、订阅事件、保存配置并在 Player 运行；普通用户可用示例和参数配置，熟悉编程者有扩展自由。不内置题材限定的战斗/背包/任务框架。

## 当前基础与边界

`Engine/Components/Script*` 有运行基础，LuaBackend 位于集成测试目录；编辑器 ScriptableComponent 还不能代表生产运行已贯通。优先生产化已有 Lua 路线。新增语言按独立适配器评估，不先维护多个脚本栈。

通用属性描述提供稳定 ID、类型、单位/坐标系、范围、默认值、可读写能力和运行/编辑入口。优先适配现有组件；Inspector、脚本、Sequence、Agent 共用语义，编辑态写入仍走文档模型与 UndoRedo。运行态每帧控制与编辑事务分开。

## 设计约定

脚本提供生命周期、实体/组件句柄、输入、时间、事件、基础物理查询、日志与配置。过期句柄、脚本异常、重复订阅和场景切换有确定语义。脚本/物理/Sequence 的写入所有权必须定义，不能由偶然调用顺序决定。

脚本能力边界按项目配置；禁止默认获得不必要的系统执行能力。热重载明确状态迁移/重启语义，失败保留上一个可运行版本。错误显示文件、行、实体和可跳转入口。

## 端到端验收

使用“靠近按钮→触发门开关→显示状态→保存→重启→Player”场景：用户能通过示例接入，而不是被迫学习整个内部 ECS/ABI。分别测新手修改参数、开发者编写脚本的完成率和调试耗时；编写脚本所需代码编辑是本领域正常成本，但不能要求修改引擎或手工修场景文件。

录像检查 Inspector、错误面板、代码跳转和运行状态；异常不能淹没界面、遮挡退出操作。代码验收检查精确结果和失败边界，压力/冒烟只作补充。

## 详细设计与接口契约

> 本节是拟议实施合同，尚未实现。类名/记录名/API 操作是概念命名；实施时对齐现有 Registry、ABI 与文档 schema，不表示这些命令已经可调用。严格关口和量化规则见 [阶段验收合同](stage-acceptance-contract.md)，结果使用 [验收模板](acceptance-record-template.md)。

| 设计项 | 本模块约定 |
|---|---|
| 数据模型 | `ScriptType/ScriptInstance/PropertyDescriptor/EventBinding`；业务身份稳定，不以原生地址/数组位置作持久引用 |
| 字段/版本 | typeId/instanceId、backendVersion、参数类型/单位/权限、eventId、订阅token、状态迁移版本；持久文档带 schemaVersion，派生记录 inputHash/toolVersion |
| 接口/执行 | create/start/fixed/update/late/stop、get/set/subscribe；编辑态事务与运行态写入分离 |
| 数据/运行路径 | 正式Lua目标→场景挂载/序列化→宿主唯一tick→重载/状态→Player导出/加载 |
| 失败/恢复 | 语法错保留可运行旧版本；运行异常定位实体/文件/行；销毁解绑；producer先join再shutdown |
| 修改归属 | 沿源码复核表中既有核心/适配器/文档/编辑入口扩展；领域服务与数据独立，UI/CLI 共用，编辑写入走文档/Undo，运行写入走唯一宿主 |
| 保存/迁移 | 原件与已验证产物保留；临时文件校验后提交；迁移记录字段/身份映射、丢失项、备份与恢复；未知版本不静默覆写 |
| 线程/事件/取消 | 主线程编辑事务，后台重计算/外部进程；结果带 generation/版本以拒绝晚到回调；关闭释放订阅/资源，远端取消能力分别声明 |
| 扩展成本 | 新节点/格式/适配器通过注册；不能为样例改核心或复制另一套UI/CLI；依赖只要求本阶段所需能力 |
