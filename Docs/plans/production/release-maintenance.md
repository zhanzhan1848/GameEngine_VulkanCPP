## 最终目标

从项目到独立成品、安装/分发、升级/回退与诊断有完整可重复流程；成品行为与编辑器一致。

## 当前基础与广度/深度差距

已有 PrimalBuild、Player 与导出基础；支持平台和组件必须按真实包验证。

| 维度 | 需要补齐的方向 |
|---|---|
| 广度 | 全组件运行覆盖、目标平台打包、安装分发、更新/回退、崩溃与版本维护。 |
| 深度 | 依赖齐全、可重复构建、资源兼容、存档迁移、干净机器运行和故障定位。 |

此表是规划差距，不是本轮运行审计。立项时把已有/部分/未支持状态绑定到代码、专项文档和真实操作结果，避免重复实现或误报完成。

## 真实交互与最终效果验收

全组件代表项目在开发机打包后搬到无源码/无 SDK 的测试环境；安装→运行→更新→模拟中断→回退。

至少三名未参与实现者依靠内置提示/正常帮助完成基础场景及一次失败恢复，保留操作录像、结果截图/视频、期望数据、操作数、耗时、求助与返工。作者演示不能替代该项。首次环境配置和每次制作成本分别记录；基础任务不要求重编引擎、手修场景文件或复制内部 ID。

UI 按实际支持平台检查 100%/150%/200% 缩放、最低窗口尺寸、长名称/中文、空/加载/错误/禁用状态与键盘焦点。最终效果检查真实内容或实测结果，不只检查面板排版。数值/图像误差、延迟/内存与交互预算在实施前按代表机器和夹具冻结；没有数字预算的项目须补全后才验收。

## 详细设计与接口契约

> 本节是拟议实施合同，尚未实现。类名/记录名/API 操作是概念命名；实施时对齐现有 Registry、ABI 与文档 schema，不表示这些命令已经可调用。严格关口和量化规则见 [阶段验收合同](stage-acceptance-contract.md)，结果使用 [验收模板](acceptance-record-template.md)。

| 设计项 | 本模块约定 |
|---|---|
| 数据模型 | `ReleaseProfile/PackageManifest/RuntimeComponentCodec/UpdateRecord`；业务身份稳定，不以原生地址/数组位置作持久引用 |
| 字段/版本 | target/arch/backend、组件支持版本、相对资源/哈希、entryScene、productVersion、migration/rollback；持久文档带 schemaVersion，派生记录 inputHash/toolVersion |
| 接口/执行 | cook/package/validate/launch/install/update/rollback；成功必须真实可加载产物 |
| 数据/运行路径 | 复用Build/Exporter/Player→完整依赖→隔离cook→相对包→宿主tick/输入→安装分发 |
| 失败/恢复 | 断包/哈希错阻止运行并诊断；更新先stage再切；旧版本/配置备份可回退 |
| 修改归属 | 沿源码复核表中既有核心/适配器/文档/编辑入口扩展；领域服务与数据独立，UI/CLI 共用，编辑写入走文档/Undo，运行写入走唯一宿主 |
| 保存/迁移 | 原件与已验证产物保留；临时文件校验后提交；迁移记录字段/身份映射、丢失项、备份与恢复；未知版本不静默覆写 |
| 线程/事件/取消 | 主线程编辑事务，后台重计算/外部进程；结果带 generation/版本以拒绝晚到回调；关闭释放订阅/资源，远端取消能力分别声明 |
| 扩展成本 | 新节点/格式/适配器通过注册；不能为样例改核心或复制另一套UI/CLI；依赖只要求本阶段所需能力 |

## 不做项目与范围边界

多人联网（暂缓）；所有平台一次交付（不要求）；平台上传默认自动发布（不采用）

延后/暂缓与非目标沿用总规划中的用户决定；其他可选/外部优先/建议边界是本模块规划方案，不能冒充用户确认的永久排除。外部负责仍需接入、数据交换和真实验收。

| 阶段 | 明确不做 | 仍需保留 |
|---|---|---|
| S1 | 一种平台安装/更新；配置迁移；回退 与 诊断包/符号版本；可复现发布；平台矩阵 不在基础阶段建设 | 可靠手工闭环、失败诊断、保存/交付 |
| S2 | 诊断包/符号版本；可复现发布；平台矩阵 不提前成为验收前置 | S1通过能力/兼容，不因深度改造破坏已有结果 |
| S3 | 未选入支持清单的专项/软件/格式/设备/协议 | 扩展契约、两个用途/来源样例和承诺组合逐项实测 |

## 严格阶段、任务拆分与退出条件

### S1 从清单/预览到可搬移成品

**阶段目标：** 实际Cook状态/相对路径；组件codec；Player唯一tick；已有实现先复用，新工作仅补本阶段契约缺口。

**进入条件：** 冻结 `ReleaseProfile/PackageManifest/RuntimeComponentCodec/UpdateRecord` 最小字段、技术路线、支持平台/输入、正常与失败夹具、UI主流程及误差/性能预算；确认源码复用边界。 缺后端/工具时可继续数据原型，但真实成功路径与视觉仍标待验；渲染/材质须保持延后。

| 任务 | 工作与顺序 | 交付物/归属 | 对应用例 |
|---|---|---|---|
| T1.1 | 实际Cook状态/相对路径；先固定合法/非法数据语义 | 契约/决策记录、领域服务或适配器 | release-maintenance-S1-A01/A02 |
| T1.2 | T1.1后：组件codec；接文档/状态、保存与执行入口 | 序列化/宿主或离线任务接入、类型化错误 | release-maintenance-S1-A03 |
| T1.3 | T1.2后：Player唯一tick；提供模板/选择器、预览和修复入口 | UI/CLI同能力、默认资源、可恢复交互 | release-maintenance-S1-B01/B03/D01 |
| T1.4 | 集成后验全部必需组合，修复后复验受影响范围 | 自动结果、非实现者录像、成本/视觉证据 | 全部用例与A/B/C/D |

**交付物：** 可运行实现/接入；更新的schema/ABI/序列化或不适用说明；正常/失败夹具与参考结果；模板/内置帮助；保存/交付/关闭恢复说明；支持/排除清单；验收报告。涉及新增渲染时记录待已有专项协调。

| 用例 ID | 输入/步骤 | 通过结果 | 失败判据与证据 |
|---|---|---|---|
| release-maintenance-S1-A01 正常/参考 | 固定参考夹具，经UI与共享服务/CLI两个入口执行 | 简单项目包移到无源码路径能运行；断开原源目录不影响；每个声明组件在Player行为与编辑一致 | 值/身份/次序/误差越合同即失败；保存参考与实际输出 |
