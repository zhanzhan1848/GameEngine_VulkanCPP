## 最终目标

形成自身稳定可控的视觉特色，在明确支持的 API、质量档和设备范围内得到一致的艺术意图、可信降级和合理性能。无需复制 Unreal 全部功能；但只做静态截图相似仍不足以形成可用制作能力。

## 当前基础与边界

已有多后端、GI、GPU Driven、后处理等能力，具体支持按 [API 矩阵](../../RHI/GraphicsAPI_Parity_Matrix.md) 和 [同步语义](../../rhi-barrier-semantics.md) 为准。矩阵中的降级不得被规划文档改写成完整对等。当前可用性仍须专项运行验收，本文不重新认定全部功能通过。

以代表场景/风格预设定义稳定画面与操作；新增特性各自提出成本，不以功能数量作为目标。离线渲染输出、动画蒙皮和运行 UI 可在对应子模块接入时扩展覆盖。

## 质量与易用性约定

画质预设说明效果、代价、适用设备和降级。多 API 对齐固定资产、曝光/色彩、相机、时间与采样条件；区分艺术允许差异、数值容差和功能不支持。性能预算绑定分辨率、设备、驱动、质量档与场景，不给无条件 FPS 承诺。

隐藏内部调试参数，保留按需高级面板；用户先选可理解的风格与质量，再微调。对不可用功能给出可读说明和替代预设，不能静默黑屏或误显示已启用。

## 端到端验收

选室内、室外、透明/反射、快速运动和低配置降级场景。用户完成导入→灯光/材质设置→选择预设→运行/输出。记录调参次数、初次得到可接受画面的时间、各后端截图/视频及性能轨迹。

视觉人工检查与数值图像比较并用：数值小差异可能可见，允许的采样噪声也可能产生较大差值。通过阈值须针对场景预先定义，失败后不能扩大阈值来通过。实际 UI 截图检查状态反馈/布局，最终画面检查艺术与动态质量。
