## 1 三域拆分与算法地图

"流体求解器 = 水面渲染"是误读。本引擎把流体拆成三个域 + 一个耦合层，各域算法与显示消费端不同，渲染边界也不同。

| 域 | 典型内容 | 求解算法谱系（按实时性排序） | 本仓库现有显示消费端 | 新渲染需求 |
|---|---|---|---|---|
| 气体域 | 烟、火、云雾、爆炸 | Eulerian 网格（Stam Stable Fluids：半拉格朗日平流 + 压力投影，MAC 网格，Jacobi/PCG；涡度约束补细节）；粒子烟（advected particles） | FroxelFogPass 三 pass 体渲染、3D 纹理云原语、SparseParticleVolume 粒子→体积注入（2026-10-08 落地） | 零：求解器往现有 3D 纹理/粒子体积契约写密度即可 |
| 小水体域 | 飞溅、倒水、容器交互 | PBF（位置约束，实时友好、无条件稳定、与位置基刚体耦合便宜）→ SPH 系（WCSPH/PCISPH/DFSPH，不可压缩处理递进）；FLIP/PIC/APIC 为离线高画质路线 | PFX 渲染桥（粒子显示）、SurfaceNets（粒子→网格）、FluidRenderPass 的 FluidInputs（吃粒子位置） | 零 |
| 大水体域 | 海、河、湖 | 非"求解"：FFT 海浪谱（Tessendorf）、Gerstner、浅水方程（heightfield 实时）、flow map | FluidRenderPass 已有表面类型与参数 | **高**：观感大头（SSR/泡沫/位移/着色）属渲染建设，随渲染专项 |
| 耦合层 | 浮力、流固、障碍 | 体积排水/压力采样浮力、双向动量交换、SDF carve 障碍 | 物理模块（Jolt 刚体）+ GlobalSDF carve 概念（froxel 阴影在用同型机制） | 零 |

可选延伸（不入基础）：MPM（雪/泥/沙）、神经代理（learned advection，走 MLX 经验）、人群级交互。

## 2 现有基建盘点（2026-10-15，启动前须复核）

- **已有**：`Engine/Graphics/Fluid/FluidRenderPass`（表面类型与参数，FluidInputs 消费粒子位置，不执行求解）；`ContentTools/pipeline/PfxCacheConvert`（Alembic→pcache、VDB→pgrid 离线转换）；`Engine/ParticleFX/interop/GeometryCache`（点缓存消费入口）；FroxelFogPass/体积云/SparseParticleVolume（气体域消费端）；SurfaceNets（表面重建）；JobSystem/TaskScheduler（CPU 并行预算）。
- **没有**：任何求解器；容器/障碍/浮力配置；求解器→消费端的数据桥；烘焙/重播工具。
- **雷区**：froxel 体积 shader（FroxelDensityInject/FroxelLightIntegrate 等）处于渲染专项活跃修改区——气体域接入只写数据进现有契约，不改这些文件；GPU 求解器任何形态都住在 `Engine/Graphics/`，须等渲染专项空窗。

## 3 长久阶段（F0–F6）

阶段只表达依赖与递进，不表达日期。F1 = fluid.md 现有 S1；F2/F3 对应其 S2/S3 的两条域路线拆分；F4 起超出原 S3 范围，属本路线图新增的长久内容。

| 阶段 | 交付 | 验收要点（对齐 fluid.md 用例族） | 渲染边界 | 依赖 |
|---|---|---|---|---|
| F0 契约冻结 | `FluidSource/SolverProfile/CacheBinding` 最小字段、单位/失败语义、正常与失败夹具 | 决策记录入库；无代码 | 零 | 无 |
| F1 外部缓存路线 | 选缓存→单位报告→现有消费端预览→保存重开（fluid.md S1 原文） | fluid-S1-A01/A02/A03、B/C/D 四门 | 零（复用现有 Pass） | F0 |
| F2 气体域 CPU 求解 | 一种气体求解（Eulerian 网格或粒子烟，二选一冻结）输出密度进现有体积契约；容器/障碍 | 封闭容器 10s 质量误差≤1%、无 NaN、越界粒子 0（fluid-S2-A01/A02 沿用）；重置/降步 | 零——粒子形态走 SparseParticleVolume 桥；网格形态最多加一个 3D 纹理上传数据钩子（实施时验证，不动 shader） | F1 |
| F3 小水体域 CPU PBF | PBF 求解（JobSystem 并行）+ PFX 桥/SurfaceNets 显示 + 浮力回写 Jolt 刚体 | 静水浮体平衡浸没比/密度比误差≤5%、烘焙重播逐采样一致（fluid-S3-A01）；倾倒/移动障碍交互 | 零 | F2（契约）+ 物理 Player 链（已落地） |
| F4 GPU 迁移 | F2/F3 选定求解器的 compute 版本；预算/降级档 | 与 CPU 参考解误差带冻结；帧预算内 | **高**：新 compute pass 住 `Engine/Graphics/`，须渲染专项协调窗口 + 文件面清单 | F2/F3 稳定 + 渲染空窗 |
| F5 大水体 | FFT/Gerstner 位移 + 浅水/flow map；表面着色升级 | 视觉验收为主，随渲染专项门禁 | **全阶段属渲染建设**，本模块只提供数据/参数契约 | 渲染专项立项 |
| F6 高级扩展 | MPM、神经代理（MLX）、双向强耦合、烘焙/重播工具、外部求解器适配（Houdini 等，经集成中心登记） | 按扩展单独冻结支持清单 | 逐项声明 | 各自前置 |

## 4 测试与验证策略（长久有效）

- **确定性优先**：所有求解器支持固定种子/固定步进重放；参考夹具逐 SHA 比对（沿仓库现有 capture 纪律）。
- **数值门禁**：质量/体积守恒误差带、无 NaN/越界、稳定 dt 区间（超界拒绝或降步，不静默）、浮力参考算例（静水均匀浮体）。
- **契约门禁**：坏缓存/缺帧/版本差异→类型化错误；点缓存不静默套用变拓扑旧面索引。
- **每阶段四门**（A/B/C/D）按总规划执行；单人现状下 B 门如实标待验收。

## 5 启动触发条件（满足其一即重评）

1. 其余生产模块（除渲染延后项）S1 基础闭环完成，出现排期空位；
2. 具体项目/演示需要烟、火或交互水体内容；
3. 渲染专项空窗，F4/F5 的协调成本下降；
4. 外部模拟缓存（Houdani/VDB）成为实际输入源，F1 变为阻塞项。

## 6 决策记录

| 决策 | 内容 | 理由 |
|---|---|---|
| D1 CPU 先行，GPU 后迁 | F2/F3 一律 CPU（JobSystem），F4 才上 compute | 零渲染冲突；避开 froxel shader 活跃修改区；实时预算内 64³ 网格烟/万级 PBF 粒子可达 |
| D2 每阶段只冻结一种求解路线 | 不自研多求解器（fluid.md 边界沿用） | 基础模块克制；未选路线留可选扩展 |
| D3 气体域优先于小水体域 | F2 在 F3 前 | 消费端（体渲染）是全引擎最强基建之一，性价比最高；小水体依赖物理耦合链更长 |
| D4 大水体不单独立项 | F5 全阶段随渲染专项 | 观感价值集中在被延后的表面着色，独立推进无意义 |
| D5 显示消费端只写不改 | 求解器输出对齐现有契约（3D 纹理/粒子体积/PFX 桥） | 满足"渲染只消费确定状态，不反推求解"的模块合同 |
