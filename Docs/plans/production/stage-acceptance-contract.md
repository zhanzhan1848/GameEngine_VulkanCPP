# 严格阶段与验收合同

> 日期：2026-10-04；状态：📋 拟议实施/验收规则，未执行验收。
> 本文为 28 个领域子规划的共用合同，不新增模块或统一排期。上级：[总规划](../../2026-10-04-agent-production-and-3d-printing-roadmap.md)。

## 阶段状态与转换

状态为未开始、决策冻结、实现中、代码待验、交互待验、视觉待验、通过、失败、待依赖、延后。通过只能由所有必需证据齐备后标记。阶段可以并行做不依赖的设计，下一阶段集成不能依赖上一阶段未通过的假定能力。

| 关口 | 必须有的记录 | 不满足时 |
|---|---|---|
| 开始 S1 实现 | 支持范围、源码基线、数据/接口版本、一个成功与一个失败夹具、UI 流程、技术选择、验收数值和代表机器冻结 | 可继续原型/选型，不能声称正式阶段已进入实现或已验收 |
| S1 退出 | 本领域基础手工闭环、明确保存/重开/运行边界、全部代码用例和真实 UI 证据 | 保留失败/待验原因，不以冒烟替代 |
| S2 进入 | S1 在本阶段所需范围通过；复用契约版本不变或已迁移；新增依赖可实际调用 | 缺项为待依赖；不要求无关模块全完成 |
| S2 退出 | 深度/恢复/复用用例通过，实例/引用/事件/状态无已知回归 | 缺陷修复后重验受影响用例 |
| S3 进入 | S2 的相关范围通过；扩展协议/兼容表/预算冻结；选定可选专项清单 | 未选专项不自动加入承诺 |
| S3 退出 | 至少两个不同用途或来源的合规样例、扩展/迁移/交付用例通过 | 非支持项明确记录，不宣称全生态完成 |

范围包括输入格式/版本、平台/设备、API、数据量、精度/单位、工具/协议版本、许可/账号条件、运行模式。不得用“通用”代替清单。支持矩阵中每个承诺组合至少有一次真实成功路径；故障自动化可用模拟器。

## 代码与数据门禁 A

- 必需合同用例通过率 100%；相关既有回归通过；没有已知阻断/高严重度缺陷，任何违反必需合同的缺陷即阻止阶段通过，即使被标成低严重度。
- 正常结果用固定夹具/解析解/可信参考结果检查；边界/无效输入、删除/关闭/重开、版本变更、失败恢复均有预期值与状态。不能只有退出码或对象存在断言。
- 保存→关闭→重开比对稳定 ID、配置、引用和值；适用 Undo 的编辑行为 Undo/Redo 后文档/原生同步一致。离线任务不适用时说明原因，用原件哈希/原子提交替代。
- 涉及 Player 的模块分别验证导出、加载、唯一 tick/事件/输入、释放。编辑器预览通过不能替代 Player；不涉及运行的模块写明交付端（外部软件/浏览器/数据报告）。
- 代码构建/ABI/schema/序列化规则按 [AGENTS.md](../../../AGENTS.md)；修改 Engine 运行指定回归。新增命令 schema 从 Registry 派生，不在文档中虚构现成命令。

## 真实交互门禁 B

每阶段至少三类任务：首次使用、重复制作、一次失败恢复。至少 3 名未参与实现者，每人独立完成必需任务，不由作者口头指路；可使用内置提示/普通文档。首轮失败必须记入，修 UI 后用未接受指路的操作者或新的等价任务复验。

所有人必需目标完成率 100%，测试期间需要作者干预次数 0；至少一次保存重开/交付操作真实执行。记录操作录像、点击/输入提交数、有效操作时间、等待时间、误操作/求助/返工。若只能作者自测，B 标待验收而非降低标准。

## 成本与响应门禁 C

下列为规划默认目标，不是现有效能实测。子文档若已有更严格预算，使用较严格值；技术原型发现预算不可达须在实现前提交范围/成本调整记录，不能失败后单方面放宽。

| 项目 | 默认预算 |
|---|---|
| 主任务操作数 | 按子文档 S1/S2/S3 值，计点击/拖拽/选择/输入提交；系统选择器内部动作单列不隐匿 |
| 无口头指导的有效操作时间 | S1 ≤5 分钟，S2 ≤10 分钟，S3 ≤15 分钟；媒体/模型长计算等待和一次性安装独立记录 |
| 重复制作的手工配置 | 不重复安装/登录，不复制内部 ID，不手改场景或协议 JSON，不重编引擎；脚本领域允许正常编辑项目脚本 |
| 交互反馈 | 代表机器上普通编辑动作 p95 ≤200ms；点击长任务按钮到出现可见状态 p95 ≤500ms；取至少20次样本并保留原始值 |
| 后台等待 | 有状态/原因；支持取消时 p95 ≤1s 内显示取消请求已接受；不能以本地停止等待冒充远端取消成功 |
| 基础工具门槛 | 自带模板/本地夹具无需付费云账号；外部适配实测的安装/许可/费用/硬件另列，不宣称零成本 |

代表机器在进入阶段前记录 CPU/GPU/RAM/OS/驱动/分辨率、构建配置、样本规模；不能为了验收临时缩小既定样本。需要性能/精度基准的专项还须冻结该模块特定预算，普通 UI 响应预算不替代求解、流送或渲染性能预算。

## UI 与最终内容门禁 D

以真实编辑器/Player/外部软件/浏览器操作截图和视频验收。初始最低工作区按 900×600 逻辑像素检查；若工具需独立更大窗口，必须在冻结记录解释并提供可访问替代，不让主入口消失。100%/150%/200% 缩放、中文/长名称、空/加载/失败/禁用、鼠标/键盘均覆盖声明平台。

必需检查项违规数 0：文字与主要动作不截断/重叠；焦点可见、Tab 可到主要动作；状态有文本不只颜色；错误包含对象/原因/修复入口；长任务不封死基础导航；布局/层级/留白一致。截图掩码只能排除时间/随机信息，并记录理由。

最终内容按领域检查：角色关节、流体/物理运动、粒子、地形接缝、相机/Sequence、音频听感与时间、打印尺寸/切片、工业属性/测量、设备时序/告警、工程数值/图例。人工检查全部必需项，无已知违约；数值和图像参考均要有来源。截图“好看”不能抵消数值错误，数值正确也不能抵消无法使用。

新渲染建设仍延后。待现有专项接通的显示功能应标待依赖/待视觉，不算阶段完整通过；已声明独立子范围可单独验收，但必须先公布范围。

## 不做项与变更

每个模块单列引擎不内置、暂缓、外部负责、可选专项和阶段排除项。只有用户明确决定才能作为永久排除；规划建议注明来源。未排期不等于删除；外部负责意味着接入/交换/验收仍需要做。

变更记录包括原范围/预算、原因、源码/原型依据、新范围、受影响依赖和用户取舍依据。变更发生在重新验收前并保留原失败证据，不让合格线追着失败结果移动。

## 证据目录与完成定义

拟议报告目录：`Docs/reports/production/<module>/S<n>/`，实施时才创建。至少含 scope/decisions、自动测试与夹具/预期、交互录像/计数、UI/内容截图或音频、成本/性能原始样本、缺陷复验与结论。使用 [验收记录模板](acceptance-record-template.md)。

阶段通过需要：交付物存在、所有必需用例通过、A/B/C/D各自签注、源码/工具版本可追溯、无未解决合同缺陷、回退与迁移说明齐备。完成规划文档不等于完成阶段。
