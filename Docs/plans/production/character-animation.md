## 最终目标

外部制作的合规角色可直接导入、检查、播放和重导入，在编辑器与 Player 中得到一致的蒙皮结果。Tripo/Blender 是可选制作入口，手工导入角色不要求云账号。引擎提供清晰诊断，避免用户靠反复转换文件猜测问题。

## 当前基础与边界

`ContentTools/GltfImporter.h/.cpp` 当前面向静态网格，头文件声明 skins/animations 不支持；实际对该内容拒绝还是遗漏需实施前审计。不能以现有静态 glTF 支持作为角色已可用的证明。

优先骨骼导入、蒙皮、动作播放和简单混合；外部软件承担绑定、复杂动作编辑和重定向。高级 IK、Control Rig、运动匹配与全套角色图编辑器不作为基础支持条件。

## 设计约定

保存骨架稳定 ID、关节层级、inverse bind、权重、动作采样、插值、单位/坐标系、根运动策略。导入报告明确支持格式和限制，错误不能静默丢失。原资产与转换副本独立；重导入保留可匹配的场景引用，不匹配项给出修复列表。

动画播放器提供播放/暂停、循环、速度、动作切换、简单混合与事件，行为可由脚本/Sequence 调用。绑定检查和拓扑改动在制作流程中分离：改拓扑后不得沿用未验证的旧权重。Tripo 服务版本和能力通过适配器核对，不写死“最新”假设。

## 交互与视觉样例

合规人形、四足、非标准骨架、坏权重各一组；无云服务时完整走“导入→报告→预览动作→拖入场景→导出 Player”。至少观察近景关节弯曲、全身移动、循环接缝及切换混合，保存录像和参考姿态。渲染后端覆盖遵循 [渲染子规划](rendering-quality-and-parity.md)，不只验证 CPU 数据。

用户能从报告定位问题和选择外部修正入口；非支持形态应明确失败，不以“生成了文件”作为通过。首次安装/账号配置单独记录，重复导入不能继续要求手工复制路径或编辑清单。

## 详细设计与接口契约

> 本节是拟议实施合同，尚未实现。类名/记录名/API 操作是概念命名；实施时对齐现有 Registry、ABI 与文档 schema，不表示这些命令已经可调用。严格关口和量化规则见 [阶段验收合同](stage-acceptance-contract.md)，结果使用 [验收模板](acceptance-record-template.md)。

| 设计项 | 本模块约定 |
|---|---|
| 数据模型 | `SkeletonAsset/AnimationClip/SkinBinding`；业务身份稳定，不以原生地址/数组位置作持久引用 |
| 字段/版本 | jointId/parent、inverseBind、顶点权重、clipId/duration/sample/interpolation、unit/axis、rootMotionPolicy；持久文档带 schemaVersion，派生记录 inputHash/toolVersion |
| 接口/执行 | import/validate、AnimationPlayer play/seek/blend；原文件与规范化派生分开，骨架ID不依赖数组变动 |
| 数据/运行路径 | 静态 importer 复用→骨架/动作解码→资源保存→运行组件→Player加载；渲染蒙皮待专项协作 |
| 失败/恢复 | 坏关节/权重/动作时间拒绝并定位；重导入不匹配列修复项；停止清除运行引用 |
| 修改归属 | 沿源码复核表中既有核心/适配器/文档/编辑入口扩展；领域服务与数据独立，UI/CLI 共用，编辑写入走文档/Undo，运行写入走唯一宿主 |
| 保存/迁移 | 原件与已验证产物保留；临时文件校验后提交；迁移记录字段/身份映射、丢失项、备份与恢复；未知版本不静默覆写 |
| 线程/事件/取消 | 主线程编辑事务，后台重计算/外部进程；结果带 generation/版本以拒绝晚到回调；关闭释放订阅/资源，远端取消能力分别声明 |
| 扩展成本 | 新节点/格式/适配器通过注册；不能为样例改核心或复制另一套UI/CLI；依赖只要求本阶段所需能力 |
