## 最终目标

用户在编辑器中制作基本展示/游戏界面，绑定数据与事件，导出后无需另写一套 Player UI。提供文本、图片、按钮、容器布局、输入焦点与基础样式；题材复杂界面由项目扩展。

## 当前依据与边界

Avalonia 编辑器 UI 不等于 Player 的运行时 UI。实际可复用的运行渲染/输入能力需实施前盘点，不承诺复用编辑器控件就可运行。选定运行 UI 后端须比较字体、平台、打包、渲染叠加和许可证；选择依据记录在实施文档。

## 设计约定

UI 文档、资源身份、布局/缩放、数据绑定、事件和焦点统一序列化。预览与 Player 使用同一运行机制。默认样式和模板可直接用，允许项目替换；UI 捕获输入与场景控制要有明确顺序。绑定不存在、图片丢失、字体缺字有可定位诊断。

## 端到端验收

无脚本的静态界面可独立验收；绑定样例为“展示模型名称/计数→按钮切换状态→Player”。分别检验鼠标与键盘，窗口缩放、16:9/宽屏/较窄窗口，以及声明支持的 DPI。保存界面截图与实际运行截图，检查对齐、间距、文字基线、hover/focus/disabled、层级、对比度和图片采样。

交互目标是选择控件、布局、绑定、运行形成闭环；不要求用户同时配置外部浏览器服务或掌握 CSS 才能完成基础 UI。额外字体/素材授权和安装成本单列。

## 依赖

S1 不依赖 Agent 或导航；S2 通过 [通用属性与事件](scripting-properties-and-events.md) 连接玩法。UI 后端选择不得强迫全部引擎模块更换渲染技术。

## 详细设计与接口契约

> 本节是拟议实施合同，尚未实现。类名/记录名/API 操作是概念命名；实施时对齐现有 Registry、ABI 与文档 schema，不表示这些命令已经可调用。严格关口和量化规则见 [阶段验收合同](stage-acceptance-contract.md)，结果使用 [验收模板](acceptance-record-template.md)。

| 设计项 | 本模块约定 |
|---|---|
| 数据模型 | `UIDocument/Widget/Binding/StyleResource`；业务身份稳定，不以原生地址/数组位置作持久引用 |
| 字段/版本 | widgetId/tree、布局/锚点、text/image/fontRef、focusOrder、bindingType/property/event、主题版本；持久文档带 schemaVersion，派生记录 inputHash/toolVersion |
| 接口/执行 | create/layout/hitTest/bind/render；UI输入捕获先于场景动作；同文档预览和Player |
| 数据/运行路径 | 选后端小样→文档/资源→布局/输入→导出→Player；新增图形路径待专项协调 |
| 失败/恢复 | 缺字体/图片有占位和诊断；绑定失效不展示旧数据为正常；移除控件释放焦点 |
| 修改归属 | 沿源码复核表中既有核心/适配器/文档/编辑入口扩展；领域服务与数据独立，UI/CLI 共用，编辑写入走文档/Undo，运行写入走唯一宿主 |
| 保存/迁移 | 原件与已验证产物保留；临时文件校验后提交；迁移记录字段/身份映射、丢失项、备份与恢复；未知版本不静默覆写 |
| 线程/事件/取消 | 主线程编辑事务，后台重计算/外部进程；结果带 generation/版本以拒绝晚到回调；关闭释放订阅/资源，远端取消能力分别声明 |
| 扩展成本 | 新节点/格式/适配器通过注册；不能为样例改核心或复制另一套UI/CLI；依赖只要求本阶段所需能力 |

**阶段目标：** 组件模板/主题；响应规则；扩展控件入口；已有实现先复用，新工作仅补本阶段契约缺口。

**进入条件：** S2中本阶段所需范围有A/B/C/D通过证据，新增契约版本、依赖能力、迁移与兼容表已冻结。 缺后端/工具时可继续数据原型，但真实成功路径与视觉仍标待验；渲染/材质须保持延后。

| T3.2 | T3.1后：响应规则；接文档/状态、保存与执行入口 | 序列化/宿主或离线任务接入、类型化错误 | runtime-ui-S3-A03 |
