## 最终目标

用户能在一个位置知道“有哪些软件、哪些能力能用、哪些 Skill 能用、缺什么、如何修复”。同一服务供启动页、项目内面板、CLI 和 Agent 查询。基本编辑、打开项目与本地资产导入不依赖任何外部软件或模型服务。

## 当前依据与范围

项目浏览器 `PrimalEditor_Avalonia/Views/ProjectBrowserView.axaml` 当前为 900×600、不可调整大小，并有打开/创建项目入口。增加面板需要一并设计窗口尺寸、滚动和布局，不能简单挤入现有固定空间。现有 CLI/MCP 可复用，尚不能据此认定已有完整软件检测中心。

覆盖本地 DCC、工具 CLI、云服务和外部 harness。Tripo 属于云集成；本地 CLI、账号配置、服务连通和任务权限分开表示。应用文件存在、版本可读、脚本可调用、所需许可证可用是不同状态。

## 入口与 UI 决策

建议在启动页增加“软件与 Skills”入口和轻量摘要，例如“3 个集成可用，1 个待配置”，与打开/创建项目并列。详情使用可扩展的集成中心面板；项目内通过固定的工具入口重新打开。不要把检测做成每次启动必经向导。

启动页显示用户级集成与 Skills；项目打开后叠加项目级配置，明确来源与覆盖关系。`PRIMAL_OPEN_PROJECT` 跳过启动页时仍可访问相同功能。首次使用某项能力时，在任务旁显示该能力的缺项和解决入口。

每张卡片展示软件名称/版本、安装状态、连接或调用状态、内部/外部 Skill 数量和可用性。详情展示入口路径、多个版本、所需 capability、验证时间、失败原因、来源与安装说明。过滤“可用 / 待配置 / 未发现”，不要默认展示一整屏红色缺项。

## 数据与接口约定

- 软件记录：稳定 ID、类别、本机/远端、候选入口、版本、发现来源、检测时间、适配器版本、capabilities。
- Skill 记录：稳定 ID、说明、内部/项目/用户/外部来源、可见范围、版本、所需 capability、兼容性、最近验证结果。
- 状态分别表达“已发现、未发现、未知、配置缺失、验证失败、验证通过”；不可将“未扫描到”写成“不存在”。
- 外部 Skills 仅扫描用户指定或已注册且可访问的位置；外部 harness 无法枚举时显示“未知/未连接”。“有对应 Skill”不等于“该软件任务已验证”。
- 配置解析顺序为项目显式配置、用户配置、系统应用位置、PATH；检测结果不覆盖显式选择。版本选择和清理过期路径可撤销。
- 静态发现与实际 probe 分离；启动使用缓存和异步发现，昂贵/联网/可能占用许可证的验证按需运行。扫描不执行任意 Skill 脚本、不启动 DCC、不读取或展示凭据。
- UI 与命令共享检测服务；适配器声明 detect/probe/capabilities/execute 的语义，命令名在实现时由 Registry 确定。

S1 初始交互预算：从任一入口到指定软件详情不超过 3 次操作；手动定位与验证不超过 5 次操作（不计系统文件选择器内部操作，但单独记录）。本地缓存摘要目标在启动页可交互后 1 秒内出现；完整扫描允许后台完成，显示进度、取消和时间。这些是拟议验收目标，实施前绑定代表机器，不伪装成已测性能。

## 验收场景与证据

实际执行“只有引擎”“多个版本”“软件已装但调用失败”“有外部 Skill 但缺软件”“软件能用但没有 Skill”“离线云服务”“跳过启动页”“切换项目”。记录发现结果与实际路径、诊断截图、操作录像、点击/耗时、额外配置次数；检查键盘焦点、窄窗口、长路径和不同 DPI。必须保留未知状态，避免虚假绿色。

## 可选集成目录

Blender、FFmpeg、Tripo、FreeCAD、一个切片器、Houdini、Resolve、外部 harness 均是独立适配候选，不构成安装清单或固定接入顺序。安装引导区分官网、平台/版本、许可证/账号要求、插件桥和 Python 环境；本规划不自动安装它们。

具体软件连接方式及本机检测快照见 [工作流文档](agent-workflows-and-artifacts.md)。Skill 的制作说明与跨软件任务编排分层，避免把“显示 Skill 文件”误当成“有可靠执行器”。

## 详细设计与接口契约

> 本节是拟议实施合同，尚未实现。类名/记录名/API 操作是概念命名；实施时对齐现有 Registry、ABI 与文档 schema，不表示这些命令已经可调用。严格关口和量化规则见 [阶段验收合同](stage-acceptance-contract.md)，结果使用 [验收模板](acceptance-record-template.md)。

| 设计项 | 本模块约定 |
|---|---|
| 数据模型 | `SoftwareRecord/SkillRecord`；业务身份稳定，不以原生地址/数组位置作持久引用 |
| 字段/版本 | softwareId、候选入口/来源、version、capabilities、probeResult/time；skillId、来源/作用域、依赖/兼容性、validationResult；持久文档带 schemaVersion，派生记录 inputHash/toolVersion |
| 接口/执行 | detect/list/probe/selectVersion；查询无副作用，probe 有超时/取消，结果带 generation |
| 数据/运行路径 | 用户级配置→项目覆盖→异步发现→缓存合并→UI/CLI；重开窗口只订阅服务 |
| 失败/恢复 | 缺入口→手动定位；未知来源→未知；probe 失败→保留发现记录；切项目取消旧订阅 |
| 修改归属 | 沿源码复核表中既有核心/适配器/文档/编辑入口扩展；领域服务与数据独立，UI/CLI 共用，编辑写入走文档/Undo，运行写入走唯一宿主 |
| 保存/迁移 | 原件与已验证产物保留；临时文件校验后提交；迁移记录字段/身份映射、丢失项、备份与恢复；未知版本不静默覆写 |
| 线程/事件/取消 | 主线程编辑事务，后台重计算/外部进程；结果带 generation/版本以拒绝晚到回调；关闭释放订阅/资源，远端取消能力分别声明 |
| 扩展成本 | 新节点/格式/适配器通过注册；不能为样例改核心或复制另一套UI/CLI；依赖只要求本阶段所需能力 |

## 不做项目与范围边界

全部软件自动安装/强制启动验证（本规划不采用）；扫描外部 Skill 时执行其代码（不采用）；未注册位置自动判没有 Skill（不采用）

延后/暂缓与非目标沿用总规划中的用户决定；其他可选/外部优先/建议边界是本模块规划方案，不能冒充用户确认的永久排除。外部负责仍需接入、数据交换和真实验收。

| 阶段 | 明确不做 | 仍需保留 |
|---|---|---|
| S1 | capability/Skill 匹配；按需 probe/取消；定位/验证失败引导 与 适配器注册/迁移；项目作用域/版本选择；任务内缺项链接 不在基础阶段建设 | 可靠手工闭环、失败诊断、保存/交付 |
| S2 | 适配器注册/迁移；项目作用域/版本选择；任务内缺项链接 不提前成为验收前置 | S1通过能力/兼容，不因深度改造破坏已有结果 |
| S3 | 未选入支持清单的专项/软件/格式/设备/协议 | 扩展契约、两个用途/来源样例和承诺组合逐项实测 |
