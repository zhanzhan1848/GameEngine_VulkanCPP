## 最终目标

任何支持目标协议的 harness 均可用相同引擎能力完成制作任务；用户可通过普通 UI、CLI 或 Agent 启动、观察、取消和恢复。LLM 负责理解与规划，工具负责确定执行和校验。无需 LLM 的手工制作仍完整可用。

## 当前基础与边界

复用 `Primal.CliFramework/`、编辑器命令和 `Tools/primal-mcp/primal-mcp.mjs`。现有 `workflow.run` 是顺序命令执行，最多 64 步、失败停止，不自动回滚；跨软件长任务需独立任务层。MCP 支持的协议版本要与目标 harness 实际握手，不能仅凭“有 MCP”承诺所有客户端兼容。

本模块只管理任务、产物、软件适配与 Skills 执行约定；不替代各 DCC 的制作功能，不要求每个模块接入模型供应商。

## 共用契约

任务记录 run ID、状态、输入哈希、软件/适配器/Skill 版本、参数、步骤依赖、远端 task ID、日志、输出及验收证据。状态区分排队、运行、成功、失败、取消、结果未知及本地停止等待/远端仍在运行。

产物记录单位、坐标系、材质/纹理色彩空间、对象身份、源/派生关系、输出哈希及导入目标。源文件保留，修复/减面/打印/动画为派生版本。临时输出隔离；结构校验失败不进入正式资产库，视觉待审状态不能显示“已验收”。

重试按步骤定义幂等性；付费提交保留 task ID，提交结果未知时先查询，不直接重复扣费。外部文件恢复、进程终止和编辑器 Undo 是不同机制。缓存键包含输入、参数和工具版本；所有破坏性覆写必须声明目标与恢复方式。

Skill 包含说明、输入/输出、capability、前置条件、步骤、失败语义及验收；可有 Primal manifest，但不要求外部 harness 原生理解。内部 Skill、外部 Skill 和跨软件 Skill 共用能力描述，通过桥接读取不同来源。

适配优先官方接口，GUI 自动化只补缺口。每个适配器独立进程与依赖环境；不把全部 DCC 库装入编辑器。安装信息必须指向官方入口，并按系统/版本区分；当前机器检测快照不作为默认绝对路径。

## 独立流水线验收样例

“本地模型→规范化→引擎预览”“Tripo→模型检查→绑定/动作→引擎”“模型→打印副本→几何报告→切片器”“Sequence→帧输出→FFmpeg”。每条流水线独立声明依赖，不要求全部软件安装后才能运行一条。

每条记录真实输入、步骤耗时、一次性安装成本、每次执行人工操作、数据返工次数、质量报告和最终画面。模拟服务验证故障，不替代真实软件成功路径验证；真实软件覆盖按已声明适配版本限定。

## 详细设计与接口契约

> 本节是拟议实施合同，尚未实现。类名/记录名/API 操作是概念命名；实施时对齐现有 Registry、ABI 与文档 schema，不表示这些命令已经可调用。严格关口和量化规则见 [阶段验收合同](stage-acceptance-contract.md)，结果使用 [验收模板](acceptance-record-template.md)。

| 设计项 | 本模块约定 |
|---|---|
| 数据模型 | `RunRecord/StepRecord/ArtifactManifest`；业务身份稳定，不以原生地址/数组位置作持久引用 |
| 字段/版本 | runId、inputHash、工具/Skill版本、依赖、幂等等级、remoteTaskId、state、outputHash/validation；持久文档带 schemaVersion，派生记录 inputHash/toolVersion |
| 接口/执行 | submit/query/cancel/resume；提交返回 runId，编辑命令仍走 Registry，不跨软件承诺原子撤销 |
| 数据/运行路径 | 输入快照→计划校验→隔离工作目录→执行→验证→注册资产；失败保留日志 |
| 失败/恢复 | 取消区分本地等待与远端成功取消；未知付费提交先查 taskId；坏产物隔离 |
| 修改归属 | 沿源码复核表中既有核心/适配器/文档/编辑入口扩展；领域服务与数据独立，UI/CLI 共用，编辑写入走文档/Undo，运行写入走唯一宿主 |
| 保存/迁移 | 原件与已验证产物保留；临时文件校验后提交；迁移记录字段/身份映射、丢失项、备份与恢复；未知版本不静默覆写 |
| 线程/事件/取消 | 主线程编辑事务，后台重计算/外部进程；结果带 generation/版本以拒绝晚到回调；关闭释放订阅/资源，远端取消能力分别声明 |
| 扩展成本 | 新节点/格式/适配器通过注册；不能为样例改核心或复制另一套UI/CLI；依赖只要求本阶段所需能力 |

## 不做项目与范围边界

替代各 DCC 功能（不内置）；所有模块强制 LLM（不采用）；跨软件自动回滚承诺（不做）；游戏联网暂缓

延后/暂缓与非目标沿用总规划中的用户决定；其他可选/外部优先/建议边界是本模块规划方案，不能冒充用户确认的永久排除。外部负责仍需接入、数据交换和真实验收。

| 阶段 | 明确不做 | 仍需保留 |
|---|---|---|
| S1 | 步骤依赖/缓存；恢复边界；云适配/付费结果查询 与 harness握手/兼容表；Skill桥接；第三方适配例 不在基础阶段建设 | 可靠手工闭环、失败诊断、保存/交付 |
| S2 | harness握手/兼容表；Skill桥接；第三方适配例 不提前成为验收前置 | S1通过能力/兼容，不因深度改造破坏已有结果 |
| S3 | 未选入支持清单的专项/软件/格式/设备/协议 | 扩展契约、两个用途/来源样例和承诺组合逐项实测 |

## 严格阶段、任务拆分与退出条件

### S1 本地可恢复任务

**阶段目标：** 复用现有转换/编码；任务状态与工作目录；报告→预览→资产接收；已有实现先复用，新工作仅补本阶段契约缺口。

**进入条件：** 冻结 `RunRecord/StepRecord/ArtifactManifest` 最小字段、技术路线、支持平台/输入、正常与失败夹具、UI主流程及误差/性能预算；确认源码复用边界。 缺后端/工具时可继续数据原型，但真实成功路径与视觉仍标待验；渲染/材质须保持延后。

| 任务 | 工作与顺序 | 交付物/归属 | 对应用例 |
|---|---|---|---|
| T1.1 | 复用现有转换/编码；先固定合法/非法数据语义 | 契约/决策记录、领域服务或适配器 | agent-workflows-and-artifacts-S1-A01/A02 |
| T1.2 | T1.1后：任务状态与工作目录；接文档/状态、保存与执行入口 | 序列化/宿主或离线任务接入、类型化错误 | agent-workflows-and-artifacts-S1-A03 |
