## 现状（基于代码阅读）

### 1. Docking
- 工具栏 + Hierarchy/Viewport/Inspector 静态布局（Grid 列 250/* /300）
- 多个 Asset Editor Window 独立（多窗口）—— 不是 docking
- **缺**：Tab 拖拽 / 浮窗 / 主窗口内 dock panel

### 2. ContentWatcher
- 已有 250ms debounce + FileSystemWatcher
- `Renamed` 事件丢失**新路径**（只 emit 旧路径）
- `Moved` vs `Renamed` 不区分（同目录 move 在 FSW 是 Renamed）
- `ContentModifiedEventArgs` 只有 `FullPath` + `ChangeType`，缺 `OldPath`/`NewPath`
- **缺**：Renamed 区分、事件丰富化

### 3. Engine asset id 序列化
- `GameEntity` C# 端有 `Components` + `Children` + `Name`
- `WorldEditorViewModel.DropAssetAsync` 调 `NativeEngineBridge.PipelineRegisterMeshEntity` 拿 native mesh content id
- `_entityNativeIds: Dictionary<GameEntity, uint>` 内存映射（P2 补全）
- **缺**：scene 序列化到 `.scene` 文件时，native id **不写**——重启后 ECS binding 失效
- 持久化方案：用 `asset path` 替代 native id（重启时通过 `ImportMeshAsync` 重建 native id，然后 `SetEntityTransform` 重建 transform）

### 4. Asset Editor Undo/Redo
- P0 修复：基类 `UndoRedo` + `TransactionAction`（scene 操作栈）
- Texture/Geometry Editor **未接入** scene `UndoRedo`——`IsDirty` 仅 UI 状态
- 修改 mip/segments/format/sizeX 等不入栈
- **缺**：settings 变更入 scene UndoRedo；或 AssetEditor 自己的 UndoRedo 栈

## 目标

1. **Docking** — Avalonia.Dock 库集成（如果可用）或自制轻量 docking（split/tab 拖拽）
2. **ContentWatcher 改进** — Renamed 给 OldPath + NewPath；`ContentModifiedEventArgs` 扩展；`Moved`（同目录） vs `Renamed`（跨目录）区分
3. **Engine asset id 序列化** — scene 保存 asset path（不是 native id），重启时 rebuild 关联
4. **Asset Editor Undo/Redo** — 接入 `WorldEditorViewModel.UndoRedo`（在 `OnPropertyChanged` 包装里 push UndoAction）

## 设计

### 1. Docking

**方案选择**：
- **方案 A**：Avalonia.Dock 库（外部包）
  - 需要 `dotnet add package Dock.Avalonia`
  - 引入新依赖（用户希望最小依赖）
- **方案 B**：自制轻量 docking（用 Grid + TabControl + 拖拽）
  - 三个 panel 拖到左右上下（snapping）
  - tab 拖到主区域 → 浮动 → 拖回

**本轮选 B**（自制约 200 行代码，无新依赖）。DockingManager.cs：
```csharp
// 简化：DockZone (Top/Right/Bottom/Left/Center)
// 每个 panel 注册一个 DockPanel; 主区域 = Grid with 4 rows + 1 col
// panel 拖到 zone 高亮 → 释放 → 重新布局
// 浮动 panel = Window with title
```
**简化范围**：本轮只做"基础 docking"——能拖出主窗变 Window、拖回主窗贴边。不做 tab reorder、layout persistence（Docking layout 与 EditorLayoutSettings 隔离，本轮不做）。

### 2. ContentWatcher 改进

```csharp
public class ContentModifiedEventArgs
{
    public string? OldPath { get; }   // Renamed 旧路径
    public string NewPath { get; }    // 新路径（创建/修改/重命名后/移动后）
    public WatcherChangeTypes ChangeType { get; }
    public bool IsMove { get; }       // true: same dir rename; false: cross-dir rename
}
```

实现：
- `Created` → OldPath=null, NewPath=path, IsMove=false
- `Deleted` → OldPath=path, NewPath=null, IsMove=false
- `Renamed`（RenamedEventArgs） → OldPath=e.OldFullPath, NewPath=e.FullPath, IsMove=目录同（old/new parent 相等）
- `Changed` → OldPath=null, NewPath=path, IsMove=false
- debounce 仍 250ms，但 batch 内部按 ChangeType 分组

订阅者（ContentBrowserView）更新 `AssetRegistry`：
- Created → `AssetRegistry.Register(NewPath)`
- Deleted → `AssetRegistry.Unregister(OldPath)`
- Renamed → `Unregister(OldPath)` + `Register(NewPath)`

### 3. Engine asset id 序列化

`Scene.cs` 序列化 `Entities[]`。当前 `GameEntity` JSON 序列化的字段名（`JsonPropertyName`）：
- Name
- IsEnabled
- IsActive
- Entities
- Components（多态 — Transform/Component 子类自己序列化）

**本轮加字段**：
- `EntityAssetPath: string?` — entity 绑定的 asset 路径（如果来自 .mesh 拖入）
- `EntityLod: int` — 绑定的 LOD（mesh asset 可能多 LOD）
- `EntityType: string?` — 类型标记 "Mesh" / "Light" / 空（默认空 = 自定义）

`Scene.FromJson` 反序列化后，`WorldEditorViewModel` 调 `LoadEntity`：
- 遍历 entity
- 如果 `EntityAssetPath != null`：
  - 调 `NativeEngineBridge.ImportMeshAsync(assetPath)` 拿 request id
  - 60s 轮询
  - `NativeEngineBridge.PipelineRegisterMeshEntity(geometryContentId)`
  - 存到 `_entityNativeIds[entity] = newNativeId`
  - `NativeEngineBridge.SetEntityTransform(newNativeId, pos, rot, scl)`

修改范围：
- `Components/GameEntity.cs` 加 `EntityAssetPath` 字段（可空）
- `WorldEditorViewModel` 加 `LoadEntity(GameEntity)` 异步方法
- 加载 project 时（`Project` setter）批量 trigger `LoadEntity`

### 4. Asset Editor Undo/Redo

**方案 A**：AssetEditor 自己的 UndoRedo 栈——和 scene UndoRedo 隔离
- 优点：settings 修改不入 scene UndoRedo，不污染场景历史
- 缺点：用户在场景外 undo 不能撤销 settings 修改

**方案 B**：AssetEditor settings 修改入 scene UndoRedo（包装 UndoAction）
- 优点：单一 UndoRedo 栈
- 缺点：AssetEditor 操作进入 scene 历史显得奇怪

**本轮选 A**：AssetEditor 自己的 UndoRedo。在 `AssetEditorHost` 加 Undo/Redo 快捷键（Ctrl+Z / Ctrl+Shift+Z）从 host `UndoRedo` 栈 pop。

实现：
- `AssetEditorViewModel` 基类加 `UndoRedo` 实例（每 editor 一个）
- Texture/Geometry 在 `IsNormalMap/OutputFormat/SizeX` setter 创建 `Action` push 到 UndoRedo
- 模式：`OnPropertyChanged` 不直接 push——而是用专门的 `RecordAction(Action)` 方法，在 VM 内部 setter 末尾调
- `Ctrl+Z` / `Ctrl+Shift+Z` 已经在 `AssetEditorHost` key binding 里（`Save/Discard`）—扩展加 Undo/Redo
