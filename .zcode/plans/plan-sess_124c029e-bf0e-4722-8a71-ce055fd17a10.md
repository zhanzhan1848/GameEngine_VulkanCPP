# 世界视口接入材质图编译着色器（v1）

## 目标

世界编辑器视口中，应用了材质图的 mesh 用**图编译出的片元着色器**渲染（与 preview 同源逐像素效果），替代现有的"三槽纹理+固定 PBR"近似；保存材质后热更新照常生效；编译失败静默回退现有固定路径。

验收：TestProject_01 中 Plane_1 应用 lion+gl_flag 经 Add 混合的材质，世界视口显示与 preview 一致的混合效果；改图→Save 无需重启即时更新。

## 关键既有事实（已探明）

- 世界管线是 **GBuffer 延迟管线**（4 RT：albedo/normal/orm/velocity）；`MetalEmitter` 非 preview 模式输出的恰好是该契约的片元（BaseColor→albedo、Roughness/Metallic→orm），**可直接作为 GBuffer 片元插入 Pass 3**，RT 格式/push constants 零改动。
- 运行时 MSL 源码编译全链路可用（`MetalShader` 对无 MTLB 魔数的输入走 `newLibraryWithSource`）；`MetalDevice::ReloadShader` 自动重建依赖 PSO。
- 生成片元的配套缺口仅两处：① 其硬编码 `VertexOut` 只有 6 字段（position/worldPos/worldNormal/uv/shadowPos0/shadowPos1），与真实 GBuffer VS 输出不匹配（Metal 按 stage_in 结构严格配对）——需新写一个配套顶点着色器；② 采样器槽位需与世界描述符布局对齐。

## 改动清单

### A. ShaderIR 微调（Engine/Graphics/ShaderIR/）
1. `MetalEmitter.h`：非 preview 模式采样器从 `[[sampler(0)]]` 改为 `[[sampler(8)]]`（世界布局：图片占绑定 0–7、采样器在 8；preview 保持 4 不变）。preview/world 两分支其余差异保持。
2. `MetalEmitter.h` 非 preview 分支：`LOAD_TIME` 改为发射字面量 `0.0f`（生成代码声明的 `struct SceneData{float time}` 与世界真实 SceneData 字节布局不一致，读 buffer(1) 偏移 0 会拿到 model.m00；接真实时间需要每帧专用 CB，放二期）。加注释说明。
3. `MaterialGraphToIR.h`：ConstantTexture 分配槽位时若将 ≥8 则记 TranslateError（编译失败→回退固定路径）。
4. `EngineTest/UnitTests/Graphics/TestShaderIR.cpp`：同步更新对 sampler 槽位的断言（若有）。

### B. 世界管线集成（ForwardSceneRenderer + 新着色器文件）

5. 新建 `Engine/Graphics/Metal/shaders/Forward/MaterialGraphVertex.metal`：配套顶点着色器 `vertexMainMaterialGraph`，从 GBuffer.metal 的 vertexMain 裁剪——读同款 AoS 顶点（buffer(20)，32B 布局）与实例数据（buffer(3)+PushConsts buffer(2)），输出**恰好** emitter 的 6 字段 VertexOut（字段顺序一致），UV 翻转 (`y=1-y`) 与 GBuffer 保持一致，shadowPos0/1 由 `sceneData.shadowMatrix0/1 * worldPos` 计算（参照 ForwardPBR.metal:115）。
6. `ForwardSceneRenderer.{h,cpp}`：
   - `CreateShaders()` 加载 `material_graph_vs_`（走现有 `LoadShaderSource` 路径）；
   - 描述符布局：`graph_material_set_layout_` = 8×SampledImage(绑定0–7) + Sampler(绑定8)；管线布局 `[global_set_layout_, graph_material_set_layout_]` + 既有 push range；
   - 新增内部类 `GraphMaterialRegistry`：
     - `Register(entity_id, json_hash, const MaterialGraph&) -> bool`：`shader_ir::CompileSync` → `CreateShader(source, Pixel, "fragmentMain")` → 复制 `gbuffer_pipeline_` 的 GraphicsPipelineDesc（RT 格式/深度/面剔除不变，vertexShader=material_graph_vs_, pixelShader=生成句柄）建 PSO；按 ConstantTexture 的 asset_path 直接读 TEXR 文件 `content::create_resource(..., preferred_device=本管线设备)` 导入纹理（最多 8 张，空槽绑 white/flat 兜底），填充每变体描述符集。变体按 json 哈希共享池化（同图多实体共用 PSO/纹理集），带引用计数；
     - 反序列化图 JSON 的方式复用 `MaterialPreviewRenderer::SetMaterialGraph` 的既有模式（`DeserializeIntoGraph`）；
     - `Clear(entity_id)` / 引用计数归零销毁（destroy_resource + DestroyShader/Pipeline/DescriptorSet）；销毁发生在帧间（PipelineRenderFrame 每帧泵 RHI GC，安全）；
     - 编译失败返回 false 且不改变实体既有状态。
   - `RenderDynamicInstances()`：在不透明技术分组前新增图材质分支——`proxy.graphVariant != 0` 且注册表可解析且 technique==GBuffer(0) 的代理，按变体分组绘制（BindGraphicsPipeline(variant)、bind 变体描述符集、push 既有 PCGPushConsts、实例上传沿用 pcg_instance_buffer_）；其余代理完全走原路径。影子通道暂不消费图（与现状一致，alpha clip 阴影是已知限制）。
7. `StandardRenderPipeline.{h,cpp}`：`RenderProxy` 增加 `u32 graphVariant{}` 字段（RenderProxy.h）；`SyncEntitiesToRenderScene` 从实体→变体映射表盖戳；`UnregisterMeshEntity` 清映射并递减引用。

### C. EngineDLL 导出（EngineDLL/RenderPipelineAPI.cpp）
8. `EDITOR_INTERFACE u32 PipelineSetEntityMaterialGraph(u32 entity_id, const char* utf8_json)`：GetStdPipeline → 反序列化 → 注册表注册并写入实体映射；返回 1 成功 / 0 失败。
9. `EDITOR_INTERFACE void PipelineClearEntityMaterialGraph(u32 entity_id)`。
10. 内部纹理导入失败/纹理数>8/编译错误均返回 0 并 `std::cerr` 日志。

### D. 托管网络（PrimalEditor_Avalonia）
11. `NativeEngineBridge.cs`：两个 DllImport（UTF8 序列化字符串参数）。
12. `INativeEngineBridgeLike.cs`：`virtual bool SetEntityMaterialGraph(uint entityId, string json) => false`；`NativeEngineBridgeAdapter` 实现转调。
13. `NativeEngineBridgeAdapter.ApplyMaterialGraph`：既有的 TryEvaluate 标量推送保留；随后取 `session.SerializeJson()` → `MaterialGraphSessionLocator.PreparePreviewJson` 展开（复用现成逻辑，磁盘 sidecar 保持可移植不动）→ 以 `_pipelineMeshEntities` 映射后的 pipeline 实体 id 调用导出；返回 false 记 Warning，实体继续用固定路径。
14. 场景热更新链路零改动：上轮实现的 `ReloadMaterial` 已会在 Save 后重新加载图并重跑 ApplyMaterialGraph，自动获得新编译产物（旧变体引用计数归零自动回收）。

## 已知限制（文档化进代码注释）
- Water/Foliage/Transparent 技术仍走固定管线；Time 冻结为 0；alpha-cut 不影响影子；velocity 恒 0（影响 TAA 收敛，编辑器模式影响有限）。
- 变体缓存键含绝对路径（会话内稳定、跨机器失效无害）。

## 二期候选
时间/动态 uniform 流送、透明/水类技术支持、alpha-cut 影子、引擎侧 TEXR 缓存去重（preview 与世界重复导入同一 .texture）。
