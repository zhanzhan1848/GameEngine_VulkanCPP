# 跨平台编译错误统一报告方案

## 目标

dev push 触发的三条平台流水线（Windows/Linux/WASM）的编译错误收集到**一个报告**里集中暴露：单次运行页面上一目了然哪些平台失败、各多少条错误、错误明细可展开。

## 架构决策：编排器 + 可复用平台工作流 + 汇总 job

三个候选里选此方案（其余两个：合并成单个巨型 workflow——文件过大且丢失独立调试能力；三工作流 + workflow_run 聚合器——聚合时机需轮询竞态、报告挂在另一次运行页面上，弱）：

```
ci.yml (push dev 触发，唯一入口)
├── preflight   → 调 ci-preflight.yml（现状不变）
├── windows     → 调 windows-ci.yml（改为 workflow_call + workflow_dispatch）
├── linux       → 调 linux-ci.yml（同上，matrix gcc/clang）
├── wasm        → 调 wasm-build.yml（同上，构建+部署留在内部，secrets: inherit）
└── compile-error-report  → needs [windows,linux,wasm]，if: always()，聚合报告
```

- 平台工作流**保留现有文件名**只改触发方式（`workflow_call` + `workflow_dispatch`，删各自 push 触发避免与编排器双跑）——diff 最小，独立手动调试能力保留
- 嵌套调用一层（编排器→平台），GitHub 支持；matrix 在被调工作流内可用；`needs` 引用编排器层 job 键
- concurrency 收敛为编排器一组 `ci-${{ github.ref }}` + cancel-in-progress（平台文件不再有 push 触发，无需各自分组）

## 各文件改动

### 1. `windows-ci.yml`（改造为可复用）
- `on:` 改为 `workflow_call + workflow_dispatch`，删除 push 触发与自身 concurrency
- 保留现有全部自托管约束（powershell/ASCII/cmd /c 重定向）
- 现有 MSVC 错误提取步骤（正则 `fatal error C\d+|error C\d+|error LNK\d+|LNK\d{4}|error MSB\d+` → msbuild-errors.log）保留
- 失败时上传制品改名 `compile-errors-windows`（msbuild-full.log + msbuild-errors.log）

### 2. `linux-ci.yml`（改造为可复用 + 错误收集）
- `on:` 改为 `workflow_call + workflow_dispatch`，删除 push 触发与自身 concurrency
- 构建步骤改为 `set -o pipefail; cmake --build ... 2>&1 | tee build-linux.log`（保留失败退出码）
- 新增失败步骤：`grep -E 'error:|fatal error:' build-linux.log > compile-errors-linux-<compiler>.log` + 上传 `compile-errors-linux`

### 3. `wasm-build.yml`（改造为可复用 + 错误收集）
- `on:` 改为 `workflow_call + workflow_dispatch`，删除 push 触发与自身 concurrency
- 构建/patch 步骤加 pipefail + tee（emcc 错误格式与 clang 同为 `error:`）
- 失败时提取 + 上传 `compile-errors-wasm`
- gh-pages 部署保留在内部（每次 push 部署，用户已确认）；编排器调用时传 `secrets: inherit`

### 4. 新增 `ci.yml`（编排器，唯一 push dev 入口）
- `permissions: contents: write`（供 wasm 部署；preflight 声明的 read 是合法子集）
- 五个 job 如上图；wasm 调用加 `secrets: inherit`
- **`compile-error-report` job**（ubuntu-latest，`if: always()`）：
  1. `actions/download-artifact@v4`（pattern: `compile-errors-*`，按平台分目录）
  2. 内联 Python 聚合：从 `needs` 上下文取三平台结果（success/failure/cancelled/skipped）；逐平台统计错误行数、按错误码分组（MSVC `C\d+/LNK\d+/MSB\d+`，gcc/clang/emcc 按 `file:line` 归并）；生成 Markdown——顶部汇总表（平台×状态×错误数），下方每平台 `<details>` 折叠明细（前 100 行）
  3. 写入 `$GITHUB_STEP_SUMMARY`（运行页面直接可见）+ 上传 `compile-error-report-${{ github.run_id }}` 制品（14 天）
  4. 报告 job 自身恒成功（失败语义由平台 job 承担）

### 5. `ci-preflight.yml`：不变

## 验证与交付

1. 本地 python 解析全部 6 个 YAML + 结构断言（job 键、needs 引用、artifact 命名一致性）
2. 用本地已有构建日志（如 /tmp/wasm-build.log）喂给聚合脚本逻辑做单元验证
3. 提交并推送 dev；流水线重新触发，运行页面即见报告 job
4. 注：分支保护的 required checks 名称将从各 workflow 名变为 `ci.yml / <job>`，如配置了保护需在 GitHub 上同步调整（一次性）

## 明确不做

- 不把报告 commit 回仓库（macOS CI 时期的历史教训：污染历史 + 竞态）
- 不改 preflight 逻辑
- 不为成功构建上传空错误制品（报告按"制品缺失=无错误"处理）
