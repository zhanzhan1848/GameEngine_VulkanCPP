# 视频录制模块总规划：A. Sequence 拍片（Sequencer+MRQ 对标） + B. Run 后渲染录屏（分析用）

两部分相互独立、共享同一套帧序列/编码/遥测惯例（PNG 主产物、ffmpeg 可选、逐帧 metrics），可分别落地。建议先做 B（小而独立，直接服务当前 GI 排查工作流），再做 A。

# Part B：Run 后渲染录屏（PrimalPlayer 逐帧录制，供后续分析）

## 关键判断：零引擎改动

PrimalPlayer 本来就把每帧渲染进**离屏 RGBA16F RenderTarget** 再 Blit 到窗口（`Tools/PrimalPlayer/main.cpp:425-458`），捕获点天然存在；`SaveRenderTargetAsPng` / `DebugReadRenderTarget` / `FlushGPU` 已由 EngineDLL 导出（编辑器视口在用）。player 侧只需在 extern 声明镜像里追加这三个函数（与现有"只镜像函数声明、不镜像 POD"纪律一致）。

录制模式语义 = **渲染帧与捕获帧 1:1**：主循环每帧 `PipelineRenderFrame` 之后对 RT 调 `SaveRenderTargetAsPng`，一张 PNG 对应一次真实渲染，无丢帧（优于外部屏幕录制；循环被读回+PNG 编码拖慢是可接受代价，GI 收敛/闪烁类分析正需要逐帧完整性）。

## PrimalPlayer 改动（`Tools/PrimalPlayer/main.cpp`，约 +100 行）

新增 CLI 参数：
- `--record <dir>`：开启逐帧 PNG 落盘（`frame_%04d.png`，目录自动创建）
- `--record-frames N`：录满 N 帧自动停（缺省/0 = 录到窗口关闭/Esc）
- `--record-every N`：帧步长，默认 1
- `--record-metrics <file.csv>`：可选，逐帧标量遥测——该帧再 `DebugReadRenderTarget` 读回 RGBA16F 算 meanLuma/min/max/captureMs，CSV 行式落盘（对齐 `editor.metrics`/`FrameMetrics` 口径，C++ 侧实现同样统计）

主循环录制点：`PipelineRenderFrame(target, ...)` 成功后按 stride 落盘；stderr 每 60 帧报进度，退出时输出 summary（frames/dir/avg captureMs）。`--video` 不做在 player——视频编码留给编辑器侧统一处理（见下）。

## 编辑器集成（`PrimalEditor_Avalonia`）

- `Common/RuntimeLauncher.cs`：Run 配置加录制选项；启用时向 player 参数列表追加 `--record/--record-frames/...`；输出目录默认 `<project>/Captures/<scene>-<yyyyMMdd-HHmmss>/`。
- 工具栏 Run 区（仿现有 api/config 下拉惯例）：加"Run 时录制"开关 + 录制帧数输入（默认 300）。`BuildService.StartPlayer` 增加 exited 回调 → 通知"录制完成"并支持一键编码 mp4（framerate 默认 30，复用 Part A 抽取的 `Common/VideoEncoder.cs`）。
- CLI 一期不加 player 录制命令（`run.record` 列入路线图）；保持 UI 触发。

## 验证

- 手动：构建后 `PrimalPlayer --scene <pkg> --record /tmp/rec --record-frames 60` → 60 张 PNG + stderr summary；metrics CSV 行数=帧数。
- C# 纯逻辑单测：录制参数拼装 builder（帧数边界/目录命名/stride）。
- `ctest -R Unit` 回归（无引擎改动，预期全绿）；`primal_smoke.sh` 不受影响。

# Part A：Sequence 拍片模块（对标 Sequencer + Movie Render Queue）

范围已定：一期轨道 = **Camera Cut（分镜头切相机）+ Transform（实体位置/旋转/缩放关键帧，相机运镜=相机实体的 Transform 轨）**；渲染走**编辑器进程内**通道；一期**零 C++ 引擎改动**（离屏渲染链 `CreateRenderTarget`→`PipelineRenderFrameForSceneCamera`→`SaveRenderTargetAsPng`、场景相机切换 `IsLookingThroughSceneCamera`、变换同步 `TransformData.ApplyTo`+`PushTransformsToNative` 全部现成）。序列资产为 JSON、求值器纯函数化，为将来独立离线进程预留。

## 实现要点

1. **求值与驱动**：Seek(frame) = 求值各轨 → `TransformData.ApplyTo` + `PushTransformsToNative`（与 UI/CLI 同路径，满足文档模型优先纪律）；渲染/播放范围包裹"快照受影响实体 pose + look-through 状态，结束恢复 + MarkProjectDirty"，期间不推 undo（track/key 编辑才推 undo）。相机 Cut 逐帧查得相机 guid → `PipelineRenderFrameForSceneCamera(entityId)`，无 cut 帧回落编辑器相机。确定性=时间完全由帧号驱动（求值无随机/墙钟）→ 同序列两遍渲染逐帧一致。
2. **时间轴 UI**（仿 Unreal 底部 Sequencer）：传输条（跳首/上帧/播放/下帧/跳尾、当前帧/fps/duration 输入）+ Canvas 自绘标尺/playhead/关键帧菱形 + 拖 playhead scrub；Add 菜单（对层级选中实体加 Transform 轨；加 Camera Cut 轨）；选中实体 + K = 当前帧记录当前 pose；右键删 key/轨；预览播放 = DispatcherTimer @ fps 逐帧 Seek。
3. **CLI**（`Cli/SequenceCommands.cs`，description 按 §6.3 写单位/坐标系/前置条件/失败语义）：`sequence.new/open/save/info`；编辑类（推 undo）`sequence.add-transform-track / add-camera-cut / add-key`（pos/rot/scale 可省=取当前 pose）/`remove-track / remove-key`；播放类 `sequence.set-frame / play / pause / stop`；`sequence.render`（`--out dir`，可选 `video=x.mp4`；输出 `{dir,frames,width,height,fps,video,videoEncoded,videoHint}`）。
4. **render 循环**：逐帧持 `_renderInProgress` 互锁（绝不与视口 tick 重入），帧间 `Dispatcher.InvokeAsync(()=>{})` 让出排空 socket 队列（仿 `editor.metrics` 已验证模式）；输出分辨率一期=视口 RT 分辨率（奇数宽高 ffmpeg scale 兜底）。
5. **序列化**：`SequenceDocument` 用 System.Text.Json 存 `.pseq` + `.meta` sidecar（AssetRegistry 惯例）；不触碰 Serializer.cs 组件 type-switch（序列不进 .scene）。
